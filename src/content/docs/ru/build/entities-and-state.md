Прежде чем принять новый запрос, приложению нужно знать актуальное состояние, имеющее отношение к делу. Понимание того, как это состояние возникло, также помогает объяснять прошлые решения. NeoHaskell соединяет эти потребности: текущее состояние сущности строится последовательным применением её событий.

**Сущность** — бизнес-объект, чьи правила вы защищаете. Это может быть бронирование, документ или счёт. В учебном проекте это одна `Cart`, идентифицируемая UUID. Её состояние помогает решать, что делать со следующей командой; история событий записывает принятые изменения.

Эта страница предполагает, что [первый рабочий срез](/ru/build/first-cart/) и [добавления в Cart](/ru/build/commands-and-events/) находятся в одном проекте `mug-shop`. Если вы пришли сюда напрямую, откройте проект, созданный в разделе «Начало работы», и сначала используйте полные контрольные точки этих двух страниц; полный файл сущности на этой странице ссылается на `CartItem` и `ItemAdded` из контрольной точки добавлений.

## Проследите одну Cart во времени

Пусть история событий одной Cart такова:

| Записанное событие | Получившееся состояние |
| --- | --- |
| `CartCreated` | У Cart есть идентификатор, идентификатор владельца и нет позиций. |
| `ItemAdded`, количество 2 | Одна позиция содержит выбранный идентификатор запаса и количество 2. |
| `ItemAdded`, количество 1 | Добавляется вторая позиция, даже если она относится к тому же запасу. |

Различие между позицией и общим количеством — выбор модели. Текущий пример не объединяет повторные добавления. Он также не удаляет товары, не фиксирует цену и не отмечает Cart как оформленную. Это отдельные бизнес-решения, заслуживающие собственных фактов и правил.

## Решите, где живёт поведение состояния

Работайте из корня проекта `mug-shop`. `src/Shop/Cart/Event.hs` владеет терминологией событий Cart и `getEventEntityId`; `src/Shop/Cart/Item.hs` владеет небольшим значением, хранящимся в каждой позиции; `src/Shop/Cart/Entity.hs` владеет записью состояния, её начальным значением и воспроизведением. Фасад предметной области в `src/Shop/Cart/Core.hs` повторно экспортирует типы сущности и событий для команд и запросов.

На странице о добавлениях уже было сказано заменить `src/Shop/Cart/Entity.hs`. Здесь объясняется порядок и границы этого файла, а затем показывается его полный текущий вариант. Если вы применяете изменение сейчас, замените файл по этому пути собранным блоком ниже. Не переносите `initialState`, `update` или `getEventEntityId` за маркер, который от них зависит.

## Прочитайте состояние и его подключение

Запись состояния Cart содержит факты, нужные последующим решениям:

```haskell
data CartEntity = CartEntity
  { cartId :: Uuid
  , ownerId :: Text
  , items :: Array CartItem
  }
```

Восстановление начинается с пустого массива и нулевого идентификатора:

```haskell
initialState :: CartEntity
initialState = CartEntity {cartId = Uuid.nil, ownerId = "", items = Array.empty}
```

Случай `CartCreated` устанавливает идентичность и владельца. Случай `ItemAdded` добавляет позицию, уже принятую командой:

```haskell
update change cart = case change of
  CartCreated created ->
    CartEntity {cartId = created.entityId, ownerId = created.ownerId, items = Array.empty}
  ItemAdded added ->
    cart {items = cart.items |> Array.push (CartItem {stockId = added.stockId, quantity = added.quantity})}
```

Функция обновления применяет принятый факт. Проверка должна происходить до записи этого факта; внешняя работа должна выполняться интеграцией, реагирующей на него. Обновление Cart не обращается к складу, не проверяет сегодняшний каталог и не пересматривает, следовало ли принять запрос.

После `initialState` и `update` свяжите сущность с типом событий с помощью помощника, экспортируемого ориентированным на фреймворк импортом `Core`:

```haskell
deriveEntity ''CartEntity ''CartEvent
```

Функция `getEventEntityId` из `Event.hs` должна быть импортирована до этого маркера. Эти связанные части — поведение, которое нужно просмотреть вместе с агентом. Маркер предоставляет связи между `CartEntity` и `CartEvent`, преобразование JSON, начальное значение по умолчанию, а также экземпляры воспроизведения и маршрутизации событий фреймворка. Он не требует, чтобы поля сущности поддерживали `Show`.

## Воспроизведение — бизнес-граница

Если не помещать проверку в `update`, воспроизведение остаётся стабильным. Если при восстановлении вчерашней Cart обращаться к сегодняшней цене товара, одна и та же история может дать другой коммерческий результат. Когда цена должна стать частью соглашения о заказе, спроектируйте событие, записывающее согласованные сумму и валюту в подходящий момент.

Запись этой цены — **проектное расширение учебного проекта**, а не поле, уже присутствующее в этой Cart. Общий вывод: сохраняйте информацию, которая придаёт прошлому решению его смысл. О текущем типе Decimal и его ограничениях см. [основы языка](/ru/build/language-essentials/#amounts-and-money).

Снимки могут уменьшить работу, нужную для восстановления сущности. Это средство повышения производительности; поведение, которому вы учитесь и которое проверяете, по-прежнему является последовательным применением записанных фактов. Сохранение и восстановление отдельно рассматриваются в разделе [эксплуатация и развитие](/ru/operate/).

## Полный текущий файл сущности

Ниже приведена собранная замена для `src/Shop/Cart/Entity.hs` относительно корня проекта `mug-shop`. Определения `CartEvent`, `CartItem` и `ItemAdded`, которые он импортирует, полностью приведены на странице [команды и события](/ru/build/commands-and-events/).

<!-- complete-file -->
```haskell title="src/Shop/Cart/Entity.hs"
module Shop.Cart.Entity (CartEntity (..), initialState, update) where

import Core
import Shop.Cart.Event (CartEvent (..), getEventEntityId)
import Shop.Cart.Events.CartCreated qualified as CartCreated
import Uuid qualified
import Array qualified
import Shop.Cart.Item (CartItem (..))
import Shop.Cart.Events.ItemAdded qualified as ItemAdded

data CartEntity = CartEntity
  { cartId :: Uuid
  , ownerId :: Text
  , items :: Array CartItem
  }

initialState :: CartEntity
initialState = CartEntity {cartId = Uuid.nil, ownerId = "", items = Array.empty}

update :: CartEvent -> CartEntity -> CartEntity
update change cart = case change of
  CartCreated created ->
    CartEntity {cartId = created.entityId, ownerId = created.ownerId, items = Array.empty}
  ItemAdded added ->
    cart {items = cart.items |> Array.push (CartItem {stockId = added.stockId, quantity = added.quantity})}

deriveEntity ''CartEntity ''CartEvent
```

## Упражнение: объясните восстановление

Дайте агенту такую историю: Cart создана, добавлены две кружки, затем ещё три. Попросите предсказать и число позиций, и общее количество. Затем пусть он продемонстрирует восстановление из `initialState`.

<details>
<summary>Подсказка для рассуждения и проверки</summary>

В текущей модели ожидайте две позиции и пять единиц. Пустая история даёт начальное состояние; одно создание даёт настоящую пустую Cart. Отклонённая команда с нулевым количеством не должна добавлять факт `ItemAdded`. Повторное воспроизведение той же принятой истории из того же начального состояния должно дать то же состояние. Не путайте это с добавлением истории дважды: повторные принятые добавления меняют результат, если приложение не спроектировало обработку дублей.

</details>

Далее: [запросы](/ru/build/queries/) превращают это состояние в информацию, полезную на экране.
