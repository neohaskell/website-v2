Пользовательский интерфейс превращает выбор в запросы и показывает их результаты. Он должен различать принятие, ещё выполняющуюся работу и ошибку, чтобы человек понимал, что произошло и что можно сделать дальше.

Веб-транспорт NeoHaskell открывает команды и запросы через HTTP. Интерфейс можно построить с помощью фреймворка, подходящего вашей команде. Текущий транспорт предоставляет API приложения и его документацию; он не является универсальным API для размещения статического фронтенда.

Наш рабочий пример — витрина учебного интернет-магазина. Добавление в корзину, ожидающее резервирование и подтверждённый заказ дают конкретные примеры разных состояний, о которых интерфейс должен сообщать.

Примеры продолжаются в том же проекте `mug-shop`. Этот урок реализует API; браузерный фронтенд — необязательный клиент, который вы добавляете рядом с проектом Neo.

## Начните с настоящего контракта

С [запущенным приложением](/ru/build/first-cart/) через `neo run` откройте `http://localhost:8080/docs`, чтобы изучить сгенерированную документацию API. Та же схема доступна по `/openapi.json` и `/openapi.yaml`.

| Назначение | Пример маршрута | Что означает успех |
| --- | --- | --- |
| Отправить бизнес-запрос | `POST /commands/add-item` | Команда Cart принята. |
| Прочитать представление | `GET /queries/cart-summary` | Возвращена страница доступных и разрешённых строк представления. |
| Исследовать интерфейс | `GET /openapi.json` | Возвращена сгенерированная схема API приложения. |

Регистрация управляет интерфейсом: команда объявляет транспорт, сервис регистрирует команду, а приложение регистрирует сервис и его запросы. HTTP-маршруты используют имена в kebab-case. Не выводите маршрут из подписи экрана вроде «оформление», если соответствующей команды нет.

## Соберите подключение HTTP-приложения

Если в проекте всё ещё используется локальное непостоянное хранилище, создайте или замените `src/App.hs` этим полным подключением. Оно открывает команды Cart и Stock и их представления через веб-транспорт. Если в `App.hs` уже есть конфигурация, аутентификация или другая политика транспорта, сохраните эти шаги и добавьте только отсутствующие регистрации сервисов и запросов.

<!-- complete-file -->
```haskell title="src/App.hs"
module App (app) where

import Core
import Maybe qualified
import Path qualified
import Service.Application (Application)
import Service.Application qualified as Application
import Service.EventStore.Simple (SimpleEventStore (..))
import Service.Transport.Web qualified as WebTransport
import Shop.Cart.Queries.CartSummary (CartSummary)
import Shop.Cart.Service qualified as Cart
import Shop.Stock.Queries.StockLevel (StockLevel)
import Shop.Stock.Service qualified as Stock

app :: Application
app = Application.new
  |> Application.withEventStore @() (\_ -> SimpleEventStore
    { basePath = Path.fromText ".neo/events" |> Maybe.getOrDie
    , persistent = False
    })
  |> Application.withTransport WebTransport.server
  |> Application.withService Cart.service
  |> Application.withQuery @CartSummary
  |> Application.withService Stock.service
  |> Application.withQuery @StockLevel
```

Из корня проекта запустите `neo build`, затем `neo run`. Откройте `/docs` и `/openapi.json`, чтобы убедиться, что зарегистрированные команды и запросы присутствуют в сгенерированном контракте до подключения браузера.

## Подключите одно действие

Эта **частичная браузерная функция JavaScript** отправляет запрос `AddItem` вашего приложения. Вызывайте её с настоящими ID из раздела [запас и оформление заказа](/ru/build/stock-and-checkout/). Она предполагает, что учебный фронтенд использует прокси того же источника для `/commands`; для разработки с разных источников нужна явная настройка CORS на сервере.

```javascript
async function addMugs(cartId, stockId, quantity) {
  const response = await fetch('/commands/add-item', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ cartId, stockId, quantity }),
  });
  const result = await response.json();
  if (!response.ok) {
    throw new Error(result.reason ?? result.error ?? 'Could not add mugs');
  }
  return result.entityId;
}
```

Это адаптированная частичная браузерная функция, а не полный файл фронтенда. Поместите её в модуль, используемый фронтендом (например, создайте `frontend/cart.js`, если браузерного кода ещё нет), и вызывайте из обработчика формы AddItem. Проект Neo не создаёт этот каталог фронтенда и не настраивает для него прокси. Аутентифицированное приложение также должно передавать учётные данные согласно настройке аутентификации. Эта локальная учебная функция не реализует полноценную сессию покупателя.

Интерфейс должен отключать случайные повторные отправки, пока запрос выполняется, показывать понятный отказ и после принятия обновлять нужный запрос. Потерянный ответ сети требует особого внимания: сервер уже мог принять запрос. Решите, как приложение обнаруживает дубли до автоматической повторной отправки записывающих запросов.

## Обрабатывайте результаты отдельно

Веб-транспорт отображает принятые ответы команд как HTTP 200. Бизнес-отказы сейчас отображаются как 400 с `reason`, а ошибки команд — как 400 с `error`. Проверяйте тело ответа вместе со статусом, а не считайте любой 400 некорректным JSON.

Ошибки аутентификации и разрешений используют 401 или 403. Незарегистрированный маршрут даёт 404. Модели чтения могут временно отставать от принятой записи, поэтому состояние интерфейса «принято, обновляем» полезно. Ограниченное повторное чтение отличается от воспроизведения записывающего запроса.

## Настройте браузерный доступ в приложении

API имеет `CorsConfig` с разрешёнными источниками, методами, заголовками и необязательным временем кэширования предварительного запроса. Этот **частичный фрагмент подключения приложения** иллюстрирует локальную политику фронтенда; для него нужны существующие импорты `Application` и `WebTransport`:

```haskell
Application.withCors @() (\_ -> WebTransport.CorsConfig
  { allowedOrigins = ["http://localhost:4321"]
  , allowedMethods = ["GET", "POST", "OPTIONS"]
  , allowedHeaders = ["Content-Type", "Authorization"]
  , maxAge = Just 600
  })
```

Примените его в конвейере приложения и используйте настоящий источник фронтенда. CORS управляет браузерным доступом, но не выдаёт бизнес-разрешений. Защищайте частную информацию с помощью [управления доступом](/ru/build/access-control/).

Создайте или замените `tests/scenarios/create-cart.hurl` этим полным API-тестом. Он задаёт повторяемую серверную границу контракта браузера до добавления фронтенда. Перед запуском `neo test` остановите `neo run`.

<!-- complete-file -->
```hurl title="tests/scenarios/create-cart.hurl"
POST http://localhost:8080/commands/create-cart
Content-Type: application/json
[]

HTTP 200
[Captures]
cart_id: jsonpath "$.entityId"

GET http://localhost:8080/queries/cart-summary
[Options]
retry: 10
retry-interval: 200

HTTP 200
[Asserts]
jsonpath "$.items[?(@.cartSummaryId == '{{cart_id}}')].itemCount" nth 0 == 0
jsonpath "$.items[?(@.cartSummaryId == '{{cart_id}}')].isEmpty" nth 0 == true
```

Из корня проекта запустите `neo test`. Проверка Hurl доказывает ответ API и последующее обновление запроса; она не доказывает, что настроены раскладка браузера, прокси или провайдер аутентификации.
