Вы можете задавать поведение приложения, не запоминая руководство по языку. Но небольшой словарный запас позволяет проверять предложение агента и задавать более точные вопросы: может ли это значение отсутствовать? Может ли операция завершиться ошибкой? Принимает ли эта функция решение или выполняет внешнее действие?

Используйте эту страницу как помощника при чтении. Примеры опираются на учебный проект интернет-магазина и обычные задачи обработки данных. Это небольшие выражения или частичные функции для настроенного модуля NeoHaskell, а не второе приложение, которое нужно устанавливать.

## Читайте конвейер слева направо

NeoHaskell часто передаёт значение через именованные шаги с помощью `|>`:

```haskell
cart.items |> Array.length
```

Это означает: «возьми позиции корзины и посчитай их». Вы использовали это выражение в `src/Shop/Cart/Queries/CartSummary.hs`. Квалифицированные имена вроде `Array.length` показывают, какой модуль предоставляет операцию.

`Core` предоставляет словарь по умолчанию. В этих учебных фрагментах опущены заголовки модулей и списки импортов; полные файлы находятся в загружаемых контрольных точках. Neo управляет настройками языка, поэтому прагмы языка в файлах приложения не нужны. Запись хранит именованные поля; `cart.ownerId` читает одно поле, а `cart {ownerId = newOwner}` создаёт обновлённое значение записи. Само создание этого значения не сохраняет событие.

## Различайте отсутствие, ошибку и работу

| Тип | Какой вопрос он делает явным | Пример |
| --- | --- | --- |
| `Maybe value` | Присутствует ли значение? | Поиск корзины может дать `Nothing` или `Just cart`. |
| `Result error value` | Удалось ли вычисление? | Декодирование JSON может дать `Err message` или `Ok value`. |
| `Task error value` | Какая работа создаст результат и как она может завершиться ошибкой? | Чтение файла или HTTP-запрос. |
| `Decision event` | Какие бизнес-факты следует принять? | Принять добавление товара или отклонить его количество. |

`case` называет варианты, которые вы обрабатываете. Этот **адаптированный частичный помощник** показывает чистую проверку входных данных:

```haskell
validateQuantity :: Int -> Result Text Int
validateQuantity quantity =
  if quantity > 0
    then Ok quantity
    else Err "Quantity must be positive"
```

`Task.yield` создаёт успешный результат задачи; `Task.throw` создаёт ошибку задачи. `Task.mapError` переводит тип ошибки на границе, а `Task.asResult` позволяет исследовать ошибку как значение. Не заменяйте содержательную ошибку значением по умолчанию только для того, чтобы код продолжил работу: вызывающей стороне может понадобиться узнать, что действие не завершилось.

`do` последовательно выполняет шаги, `<-` получает результат шага, а `let` называет локальное значение. Поэтому оркестрация приложения читается сверху вниз, не помещая каждую ветку в одну огромную функцию.

## Коллекции и идентификаторы

Используйте `Array` для упорядоченных значений, а `Map` — для значений, ключом которых является идентификатор. `Array.map` преобразует элементы; `Array.takeIf` оставляет подходящие элементы; `Array.reduce` объединяет элементы в результат. `Map.get` возвращает `Maybe`, потому что ключ может отсутствовать.

`Uuid.fromText` также возвращает `Maybe`: текст из URL не обязан быть корректным идентификатором. Успешный разбор ID устанавливает его формат, но не доказывает, что вызывающей стороне разрешён доступ к соответствующей записи.

`Text` — обычный строковый тип. Форматирование вроде `[fmt|Cart #{cartId}|]` сохраняет читаемость интерполяции. Используйте именованные типы предметной области и поля записей, чтобы реализация агента сохраняла различия вашей модели событий.

## Величины и деньги

Для числовых значений нужно определить единицы, границы и правила округления. Деньги в учебном проекте дают полезный пример: цена требует и суммы, и валюты. Тип `Decimal` предоставляет хранение с фиксированной точностью в четыре знака после запятой. В JSON он сериализуется как строка, например `"12.5000"`.

Эти **выражения, подтверждённые исходным кодом**, показывают создание и форматирование:

```haskell
Decimal.fromCents 1250 |> Decimal.formatDecimal
-- "12.5000"

Decimal.divide (Decimal.fromCents 1250) Decimal.zero
-- Nothing
```

Для валюты с двумя десятичными знаками в младшей единице `fromCents` создаёт значение из целого числа младших единиц. `toCents` отбрасывает более точную дробную часть; это не неявная политика округления. `roundTo2` — явная операция, а деление возвращает `Maybe`, потому что деление на ноль не имеет значения.

Реализация хранит `Int64`, поэтому у сумм есть границы. Сейчас её текстовый анализатор проходит через преобразование с плавающей точкой; не описывайте его как финансовый анализатор произвольной точности. Предпочитайте проверенные целые младшие единицы, если они подходят политике вашей валюты, и тестируйте округление и максимальные суммы. `Decimal` не прикрепляет валюту и не принимает за вас налоговые правила.

## Что дают трейты и маркеры

Трейт описывает поведение, которое поддерживает тип. `Mappable` разрешает преобразовывать содержащиеся значения, `Default` предоставляет начальное значение, а трейты сериализации связывают значения с JSON. Ограничение в сигнатуре функции сообщает, какое поведение ей нужно.

Помощники `deriveEvent`, `deriveCommand`, `deriveEntity`, `deriveQuery` и `deriveOutboundIntegration` приходят из `Core` и генерируют распространённые экземпляры. Они уменьшают повторяющуюся проводку, а решение, обновление состояния и проекция остаются бизнес-логикой, которую можно проверить. См. [команды и события](/ru/build/commands-and-events/) для порядка объявлений и [запросы](/ru/build/queries/#derive-and-register-the-view) для специального порядка запроса.

## Упражнение: проверьте «безопасного» помощника

В учебном проекте агент разбирает неверное количество и подставляет другое, чтобы запрос всегда завершался успехом. Объясните, почему это может нарушать запрошенное поведение, а затем предложите наблюдаемую проверку.

Одна кружка — допустимое количество, но это может быть не то, что запросил покупатель. Сохраняйте неверный ввод как ошибку и дайте интерфейсу попросить исправление. Проверьте обычное положительное значение, испорченный ввод, ноль и наибольшее количество, разрешённое политикой упражнения. Преобразования в меньшие числовые или денежные представления тоже тестируйте на границах. Проверка типов помогает различать категории, но не выбирает приемлемые бизнес-значения по умолчанию.
