Использование агента для написания кода и добавление возможности ИИ в этот код — разные отношения. Возможность приложения может кратко пересказывать заметки, создавать черновик текста или помогать интерпретировать документ. Для неё нужны собственные входные данные, разрешения, ограничения расходов, состояния ошибок и правила принятия.

Полезная первая возможность предлагает текст для проверки. В учебном интернет-магазине Джесс сгенерирует черновик описания товара из предоставленных фактов. Она сможет изучить и одобрить черновик, сохраняя работоспособность остального приложения, если провайдер недоступен.

## Оставьте возможность внутри приложения

Работайте из `mug-shop` и завершите [настройку интеграций](/ru/connect/#prepare-your-project). Поместите помощник запроса в `src/Shop/Integrations/ProductDraft.hs`. Добавьте команды и события для запроса, записи и принятия черновика в области приложения, владеющей информацией о товарах. Cart и Stock такой возможности пока не предоставляют.

Команды с результатом провайдера объявите с `InternalTransport`; пользовательский запрос черновика и одобрение остаются отдельными публичными командами. Подключите его сервис, запрос и исходящий обработчик в `src/App.hs`, следуя разделам о [командах](/ru/build/commands-and-events/) и [регистрации обработчика](/ru/connect/workflows/). Конструктор ниже предоставляет вызов провайдера; ваш рабочий процесс передаёт ему входные данные и обратные вызовы.

## Сначала смоделируйте черновик, потом делайте запрос

Рабочий процесс черновика записывает запрос, вызывает провайдера и записывает либо сгенерированный текст, либо ошибку. Принятие — отдельная команда. В примере сохраняйте идентификатор товара и идентичность запроса, чтобы задержанный ответ не перезаписал новый черновик.

Обратный вызов провайдера сообщает, что ответ успешно декодирован. Он не устанавливает фактическую точность, пригодность к публикации или соответствие правилам приложения.

## Постройте запрос OpenRouter

Этот **частичный конструктор** запрашивает короткий черновик. `modelName` приходит из выбранной конфигурации провайдера; `productFacts` содержит только одобренный ввод. `recordDraftResponse` должен проверить ответ и создать тот же тип команды, что и `recordDraftFailure`.

```haskell
Integration.outbound OpenRouter.Request
  { messages =
      [ OpenRouter.system
          "Draft a short product description using only the supplied facts."
      , OpenRouter.user productFacts
      ]
  , model = modelName
  , config = OpenRouter.defaultConfig
      { OpenRouter.maxTokens = Just 300
      , OpenRouter.timeoutSeconds = 30
      }
  , onSuccess = recordDraftResponse
  , onError = recordDraftFailure
  }
```

Адаптер получает bearer-токен из `OPENROUTER_API_KEY`. Самостоятельно выберите и проверьте доступную сейчас модель; идентификаторы моделей из старых примеров не гарантируют текущую доступность.

Ответ содержит `choices` и необязательный `usage`. Обработайте пустой массив choices. Choice включает сообщение и причину завершения: усечение или фильтрация могут сделать текст непригодным, даже если HTTP-запрос завершился успехом. Содержимое сообщения может быть обычным текстом или несколькими частями.

Эта интеграция выполняет запрос без потоковой передачи. Она подходит для фонового рабочего процесса создания черновика, но сама по себе не реализует потоковый чат, хранение разговоров или систему поиска по контексту.

## Используйте Azure AI там, где это уместно

Для запросов Azure нужны явно проверенная конечная точка и скрытый API-ключ. Помощник находится в `Integration.AzureAI`. Сначала вызовите:

```haskell
AzureAI.azureEndpoint endpointText
```

Он возвращает `Result Text AzureEndpoint`; обработайте неверную конечную точку как проблему конфигурации. `azureEndpointAllowing` разрешает дополнительные доверенные суффиксы хоста для вашего развёртывания. Управлять этими суффиксами должны операторы.

**Фрагмент выражения** после проверки и при наличии настоящей неявной привязки конфигурации:

```haskell
AzureAI.chatCompletion
  validatedEndpoint
  [AzureAI.system "Use only supplied product facts.", AzureAI.user productFacts]
  deploymentName
  recordDraftResponse
  recordDraftFailure
```

Помощник читает `?config.azureAiApiKey :: Redacted Text`. Для явной передачи учётных данных создайте `AzureAI.Request` с `apiKey` и конфигурацией, в которой `endpoint` — проверенное значение. Не используйте голую конфигурацию по умолчанию как полную настройку конечной точки. В исходном коде зафиксирована версия API по умолчанию; проверьте совместимость с вашим развёртыванием.

## Проведите черновик через рабочий процесс

После добавления сервиса и обработчика черновика в `mug-shop` запустите `neo build`. Для фиксированных ответов используйте `neo test`; этим проверкам не должна требоваться живая модель. Запустите `neo run` с учётными данными провайдера, запросите черновик и исследуйте его запрос. Убедитесь, что сгенерированный текст остаётся неодобренным, пока отдельная команда принятия не завершится успешно.

## Дайте Джесс свидетельства помимо красивого абзаца

> **Агент:** «Модель вернула описание, поэтому я его публикую».
>
> **Джесс:** «Покажи команду, которая одобряет публикацию. Сгенерированный текст должен оставаться черновиком, пока я его не приму».

Проверьте обработку ответа на фиксированных наборах до проверки живой модели. Проверьте отсутствие choices, нежелательные утверждения, усечение, отказ провайдера и ответ, пришедший после изменения фактов о товаре. Соберите небольшой набор фактов о товарах и неприемлемых результатов. Живые вызовы провайдера проверяют соединение и пригодность для вашей нагрузки, а модульные тесты — детерминированные правила.

[Оговорка о повторных HTTP-запросах](/ru/connect/http-and-payments/#understand-the-current-retry-boundary) также относится к вызовам провайдера. Тайм-аут не доказывает, что оплачиваемая работа не выполнялась. Установите политику расходов приложения и согласуйте тайм-ауты запросов провайдера с [бюджетом диспетчера](/ru/connect/documents/#budget-the-entire-operation).

**Упражнение:** добавьте в учебный проект действие повторной генерации. Решите, может ли старый выполняющийся ответ заменить новый, а затем протестируйте ответы, пришедшие в обратном порядке.

Продолжайте с [инструментами ИИ](/ru/connect/ai-tools/) только когда будете готовы разрешить модели предлагать структурированные действия.
