PDF или аудиозапись содержит информацию, которую вы хотите использовать в приложении. Извлечение может превратить её в текст для поиска или черновик для проверки, а исходное вложение останется свидетельством. Решение о достаточной точности результата — отдельный шаг.

NeoHaskell включает локальное извлечение текста из PDF, извлечение документов с помощью ИИ и транскрибацию аудио. Локальное извлечение оставляет обработку на вашем сервере. Пути с ИИ отправляют содержимое файла внешнему провайдеру и добавляют вопросы стоимости, задержки и точности.

Предварительно изучите [загрузку файлов](/ru/connect/files/), [жизненный цикл интеграции](/ru/connect/) и команду результата для записи итогов. Для практики используйте небольшой PDF о кружках и извлеките из него черновые сведения для каталога.

## Продолжите с загруженным файлом

Используйте конфигурацию загрузки `mug-shop` из раздела [файлы](/ru/connect/files/) и завершите [настройку интеграций](/ru/connect/#prepare-your-project). Поместите рядом с другими интеграциями приложения помощник вроде `src/Shop/Integrations/ExtractArtworkText.hs`. Он получает уже принятое командой вложения значение `FileRef`.

Объявите команду результата обработки с `InternalTransport` и добавьте её в нужный сервис до подключения исходящего обработчика в `src/App.hs`. Результату нужен идентификатор попытки обработки, чтобы поздний ответ не мог молча заменить новую попытку. Запрос ниже — часть рабочего процесса, отвечающая за извлечение.

## Начните с цифрового PDF

Этот **частичный конструктор** запрашивает первые две страницы. `attachment`, `recordExtraction` и `recordFailure` — значения вашего приложения. Оба обратных вызова создают один тип зарегистрированной команды.

```haskell
Integration.outbound PdfExtract.Request
  { fileRef = attachment
  , config = PdfExtract.defaultConfig
      { PdfExtract.layout = PdfExtract.PreserveLayout
      , PdfExtract.pageRange = Just (1, 2)
      }
  , onSuccess = recordExtraction
  , onError = recordFailure
  }
```

Зарегистрируйте охватывающий обработчик, как показано в разделе [рабочие процессы](/ru/connect/workflows/). Текущий экземпляр выполнения находится в `Integration.Pdf.ExtractText.Internal`; сохраните эту зависимость в полном помощнике.

Установите `pdftotext` и `pdfinfo` в среду выполнения приложения. Интеграция получает байты файла, записывает временный PDF, запускает эти инструменты и возвращает текст, количество страниц и необязательные метаданные. `PreserveLayout` сохраняет расположение, `RawText` убирает это предпочтение, а `Table` использует вариант извлечения с фиксированной шириной. Результат — текст, а не разобранные записи вроде товаров или позиций документа.

Если извлечение метаданных не удалось, но извлечение текста прошло, текущая реализация может вернуть количество страниц `0` и `Nothing` в метаданных. Это означает отсутствие метаданных, а не обязательно документ из нуля страниц.

В отсканированной странице может не быть выбираемого текста. Локальное извлечение PDF не является OCR. Проверяйте пустой результат до того, как считать извлечение полезным результатом приложения.

## Используйте ИИ, когда содержимое нужно интерпретировать

`Integration.Ocr.Ai.Request` принимает `fileRef`, `mimeType`, `model`, `config`, `onSuccess` и `onError`. Его экземпляр выполнения находится в `Integration.Ocr.Ai.Internal`.

Конфигурация предлагает режимы извлечения `FullText`, `Summary` и `Structured`. `Structured` меняет подсказку, но не превращает возвращённый `Text` в проверенные данные приложения. Разберите результат и примените те же правила, что и к человеческому вводу; в примере это правила товаров.

Выберите текущую поддерживаемую модель для своего типа файла и передайте `OPENROUTER_API_KEY`. Адаптер отправляет файл целиком как вложение. `maxPages` — инструкция в подсказке, а не механизм усечения полезной нагрузки или жёсткий предел расходов. Сейчас реализация возвращает `Nothing` и для `pageCount`, и для `confidence`.

## Добавляйте аудио только при настоящей необходимости

Для записанных заметок `Integration.Audio.Transcribe.Request` использует тот же шаблон ссылки на файл. Его экземпляр выполнения находится в `Integration.Audio.Transcribe.Internal`. Конфигурация включает подсказку языка и `maxDurationSeconds`; последнее просит модель ограничить транскрибацию, но всё равно загружает полный файл.

Текущий результат предоставляет текст расшифровки, а `duration`, `confidence` и `language` всегда равны `Nothing`. В этой реализации нет разбитой на части или потоковой транскрибации. До построения рабочего процесса проверьте, принимает ли выбранный провайдер или модель настоящее кодирование вложения и тип медиаданных.

## Рассчитайте бюджет всей операции

Тайм-аут диспетчера интеграций по умолчанию равен 30 секундам. Для OCR по умолчанию задан тайм-аут запроса 120 секунд, для аудио — 180 секунд. Один только более длинный тайм-аут запроса не продлевает охватывающий тайм-аут обработки события.

Этот **фрагмент подключения приложения** даёт всей работе с событием четыре минуты; настройте его по измеренному поведению и требованиям параллельности:

```haskell
    |> Application.withDispatcherConfig @()
        (\_ -> Dispatcher.defaultConfig
          { Dispatcher.eventProcessingTimeoutMs = Just 240000 })
```

Некоторые ошибки подготовки — отключённая загрузка файлов, отсутствие файлов или отсутствующий исполняемый файл PDF — создают ошибки интеграции до обратного вызова результата. Отслеживайте ошибки выполнения вместе с командами результата; иначе документ может навсегда остаться «обрабатывается».

## Проверьте извлечение в работающем проекте

После добавления команды результата и обработчика запустите `neo build` и `neo test` из `mug-shop`. Запустите `neo run` в среде с нужными исполняемыми файлами PDF. Загрузите небольшой собственный PDF, передайте его ссылку через команду вложения и изучите статус обработки и извлечённый текст. Сохраните в `tests/` фикстуры для пустого результата и отсутствующих метаданных, а также для полезного текста.

## Упражнение: неверный размер товара

Расширьте учебный проект рабочим процессом, в котором извлечённые размеры требуют проверки до публикации. Сыграйте обе роли: загрузите пример документа, затем проверьте предложенные значения до их одобрения.

<details>
<summary>Предлагаемые проверки</summary>

Проверьте чистый цифровой PDF, скан, пустой результат извлечения, отсутствующий файл, отсутствующий исполняемый файл, тайм-аут, искажённый структурированный текст и правдоподобный, но неверный размер. Сохраняйте исходное вложение и идентичность попытки обработки. Одобрение черновика должно быть отдельной командой со своими правилами; уверенность модели недоступна из этих адаптеров.
