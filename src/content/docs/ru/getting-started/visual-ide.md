Вы создали корзину и прочитали её итог в [упражнении о первой корзине](/ru/build/first-cart/). Теперь проследите это же поведение в Neo IDE: отправленный запрос, записанный им факт и прочитанную вами информацию. Продолжайте работать в `mug-shop` — проекте, созданном при настройке.

Используйте IDE вместе с проверками поведения. Согласованный граф помогает понять изменение, но не доказывает, что приложение выполняет задуманную политику.

## Увидьте модель до открытия кода

![Neo IDE в mug-shop показывает связанную возможность первой корзины: синюю команду CreateCart, оранжевое событие CartCreated и зелёный запрос CartSummary.](/screenshots/neo-ide-overview.png)

*Первая возможность корзины: создание, записанный факт и итог. Выберите любой снимок экрана, чтобы увеличить его, не покидая страницу.*

Прочитайте картину в три прохода:

1. **Найдите запрос.** Синяя карточка `CreateCart` обозначает запрос корзины. Проследите стрелку вниз к оранжевому факту `CartCreated`.
2. **Найдите информацию, которую видит человек.** Зелёная карточка `CartSummary` получает информацию из `CartCreated`. Среди её полей есть `itemCount` и `isEmpty`. IDE называет такие зелёные карточки **запросами**; они представляют сторону модели чтения приложения.
3. **Найдите место для работы.** Левая панель перечисляет главы и срезы. Здесь `CreateCart` и `CartSummary` делят главу Cart на небольшие части, которые можно обсудить с агентом.

Сравните это с [готовыми моделями событий](/ru/start/event-modeling/). Эти рисунки проводят один пример через время, включая последовательные экраны и конкретные значения. Граф IDE показывает повторно используемые команды, типы событий и запросы: одна карточка `CartSummary` может описывать представление после множества разных историй. Её стрелки описывают связи в модели, а не живую трассировку выполняющихся запросов.

## Продолжите в проекте корзины

Если вы уже открывали IDE во время упражнения с корзиной, оставьте это окно открытым. В противном случае запустите команду из каталога, содержащего `src/` приложения корзины:

```sh
neo ide
```

Используйте каталог `mug-shop`, созданный при настройке. Ниже вы синхронизируете его модель с кодом корзины, добавленным в `src/Shop/Cart/`.

Откройте напечатанный адрес, обычно `http://127.0.0.1:2323`. IDE привязывается к каталогу проекта, из которого вы её запустили. Перед редактированием проверьте рабочее пространство, показанное в статусе соединения. IDE и HTTP-сервер приложения — отдельные процессы с разными портами.

Модель находится в `event-model.json` в корне проекта. В свежем проекте этого файла может ещё не быть. Создайте модель с помощью элементов управления холста и внесите небольшое изменение, чтобы автосохранение записало её. В новом рабочем пространстве проверьте, что смотрите не на старую модель из локального хранилища браузера: **New** создаёт пустую модель, а **Open** читает файл текущего рабочего пространства.

При подключении изменения сохраняются автоматически. Дождитесь статуса сохранения перед закрытием и используйте Git для хранения значимых версий. Cmd/Ctrl-S записывает ожидающее автосохранение, но не создаёт коммит Git.

## Свяжите картину с исходным кодом

Когда в рабочем пространстве появился файл модели, запустите эти команды из другого терминала в том же проекте:

```sh
neo inspect
neo inspect sync
neo validate
```

`neo inspect` сообщает найденную структуру предметной области. `neo inspect sync` обновляет модель по исходному коду и записывает файл модели. `neo validate` проверяет её схему и ссылки, не изменяя модель. После синхронизации через CLI нажмите **Open** в IDE (или перезагрузите её), чтобы прочитать сохранённую модель; одна запись через CLI не рассылает обновление через наблюдатель исходных файлов. Отсутствующий файл модели считается ошибкой проверки, поэтому сначала создайте и сохраните модель.

IDE также наблюдает за изменениями исходного кода и пытается выполнить ту же синхронизацию. Изменение поля существующего узла задумано так, чтобы сохранять раскладку; вновь обнаруженная структура может запустить более широкое обновление раскладки. Проверяйте результат после крупного рефакторинга.

Сейчас синхронизация выполняется **из кода в модель**. Редактирование картины не генерирует соответствующий код приложения. Обсудите желаемую модель с агентом разработки, позвольте ему изменить исходный код и сравните обновлённую картину со своим намерением.

## Прочитайте небольшой фрагмент поведения

Найдите `CreateCart` и проследите его до `CartCreated`, а затем до `CartSummary`. Свяжите эти имена с запросом, который отправляли, и с увиденным итогом пустой корзины. Попросите агента показать, где идентификатор корзины проходит через этот путь.

## Возвращайтесь сюда по мере роста корзины

После добавления `AddItem` в разделе [команды и события](/ru/build/commands-and-events/) снова синхронизируйте тот же проект и выберите эту команду. Какая информация ей нужна и что она запишет при принятии? На следующем снимке показано, что вы сможете тогда проверить.

![Выбор синей команды AddItem подсвечивает её стрелку к оранжевому событию ItemAdded. AddItem содержит cartId, stockId и quantity; ItemAdded содержит entityId, stockId и quantity. Остальные узлы затемнены.](/screenshots/neo-ide-detail.png)

*Выбор `AddItem` подсвечивает её связь с `ItemAdded`. При увеличении поля становятся читаемыми, а окружающая модель остаётся видимой для контекста.*

Здесь можно проследить конкретную информацию: `quantity` входит в команду и появляется в принятом событии. Запрошенный `cartId` идентифицирует корзину, чьё событие содержит `entityId`. Попросите агента показать соответствующее правило в исходном коде и продемонстрировать, что ноль отклоняется. Имя поля `quantity` говорит, какая информация перемещается; оно не говорит, какие значения принимает правило.

Используйте элементы управления холстом **+** и **−**, чтобы изменить масштаб. Выбор узла подсвечивает его связи. Если картина вышла за пределы видимой области, попробуйте **Fit View**; повторное открытие или перезагрузка сохранённой модели также возвращает удобный начальный кадр.

По мере роста модели приложения используйте её возможности и главы, чтобы сосредоточиться на одном поведении. Прослеживайте связи через границу, когда исследуете другую предметную область или внешнего провайдера. **Tidy by flow** меняет представление, но не исправляет бизнес-правила. Панель Problems помогает находить ошибки проверки модели.

**Heal with AI** — необязательное действие восстановления модели, которое вызывает настроенный поток Claude CLI. Для обычного просмотра, инспекции, проверки и детерминированной синхронизации это действие не нужно. Проверяйте его изменения так же, как предложение другого агента; это не доказательство поведения во время выполнения.

## Знайте текущий охват

Холст Model реализован. Линзы Schema, Logs и Emulate пока показывают заполнители для будущей работы. Для [эксплуатационных свидетельств](/ru/operate/observability/) используйте настоящие журналы приложения и тесты.

Для локальной работы оставляйте привязку к loopback по умолчанию. Привязка с помощью `--host 0.0.0.0` открывает IDE на других сетевых интерфейсах; локальные инструменты рабочего пространства не следует считать пользовательским интерфейсом производственной системы.

## Ваша проверка

Предскажите, что сделает второй запрос `CreateCart` в уже созданной возможности. Отправьте его и найдите оба идентификатора в итоге. На графе по-прежнему один узел `CreateCart`: он описывает вид запроса, а не каждое его возникновение. Попросите агента найти код, выбирающий новый идентификатор, а затем проследите это поле от команды к событию и запросу.

После следующего урока вернитесь и проверьте отказ для нулевого количества. Карточка `AddItem` называет запрос; её функция решения определяет, какие значения принимаются.

Далее: в разделе [команды и события](/ru/build/commands-and-events/) объясняется решение, лежащее за этими связями. Для отдельных команд обратитесь к [справочнику CLI](/ru/reference/cli/).

Свидетельства реализации: [сервер IDE](https://github.com/neohaskell/NeoHaskell/blob/main/neo/src/commands/ide.rs), [синхронизация исходного кода](https://github.com/neohaskell/NeoHaskell/blob/main/neo/src/ide/sync.rs) и [текущие линзы](https://github.com/neohaskell/NeoHaskell/blob/main/neo/assets/ide/src/ui/lenses/lenses.tsx).
