Ваш первый рубеж — собственный проект. Вы создадите его с помощью `neo`, инструмента командной строки NeoHaskell, а затем будете развивать его в следующих главах. В одном каталоге будут находиться код, тесты, конфигурация и визуальная модель.

Учебный проект называется `mug-shop`. Это небольшое приложение, которое вы сейчас начнёте создавать. Можно выбрать другое имя и использовать соответствующий каталог везде, где руководство говорит `mug-shop`.

## Подготовьте инструменты

Используйте macOS или Linux; в Windows работайте внутри WSL2. Установите Git и [Nix для своей операционной системы](https://nixos.org/download/). Nix предоставляет компилятор и зависимости сборки, выбранные проектом. Отдельно устанавливать GHC или Cabal не нужно.

В новом терминале проверьте, что обе команды доступны:

```sh
git --version
nix --version
```

Neo использует flakes Nix. Если в вашей установке Nix они ещё не включены, добавьте следующую строку в `~/.config/nix/nix.conf`, сохранив уже существующие настройки:

```ini
experimental-features = nix-command flakes
```

## Установите Neo

Скачайте исполняемый файл для своего компьютера из раздела [релизов Neo](https://github.com/neohaskell/NeoHaskell/releases/latest).

:::note[Требование к версии]

Для этих примеров нужен такой релиз Neo, в котором зафиксированная стартовым фреймворком версия экспортирует все пять вспомогательных функций `derive…` через `Core`, включая `deriveEntity`, и использует соответствующий пресет компилятора Neo. После `neo new` сохраните созданную фиксацию `neo-version`; если стартовый проект не предоставляет эти функции, установите релиз с совместимой версией фреймворка до изменения исходных файлов. Добавлять настройки языка в исходные файлы не потребуется.

:::

| Компьютер | Скачивание |
| --- | --- |
| macOS, Apple silicon | `neo-aarch64-apple-darwin` |
| macOS, Intel | `neo-x86_64-apple-darwin` |
| Linux или WSL2, Intel/AMD 64-bit | `neo-x86_64-unknown-linux-gnu` |
| Linux, ARM 64-bit | `neo-aarch64-unknown-linux-gnu` |

Например, на Mac с Apple silicon:

```sh
mkdir -p "$HOME/.local/bin"
curl -fL https://github.com/neohaskell/NeoHaskell/releases/latest/download/neo-aarch64-apple-darwin -o "$HOME/.local/bin/neo"
chmod +x "$HOME/.local/bin/neo"
export PATH="$HOME/.local/bin:$PATH"
neo --version
```

Для другой платформы замените последнее имя файла в URL скачивания на имя из таблицы. Имя файла назначения оставьте `neo`. Добавьте строку `export PATH` в файл запуска оболочки (`~/.zshrc` для zsh или `~/.bashrc` для bash), чтобы Neo был доступен и в будущих терминалах. В релизе есть файл `SHA256SUMS`, если вы хотите проверить контрольную сумму скачанного файла.

Команда выводит установленную версию Neo. `command -v neo` показывает, какой исполняемый файл нашла оболочка. При обновлении проверьте оба результата, чтобы старая установка не оказалась раньше в вашем `PATH`.

## Создайте приложение

Из каталога, где вы храните проекты:

```sh
neo new mug-shop
cd mug-shop
neo build
```

Примите сведения о проекте или выберите свои, когда Neo задаст вопросы. `neo new` создаёт приложение с небольшим стартовым кодом, набором тестов и зафиксированными зависимостями. `neo build` компилирует его. Первая сборка может занять больше времени, пока зависимости скачиваются или собираются; последующие сборки используют результат этой работы. Nix может спросить, доверяете ли вы объявленным проектом бинарным кэшам.

Стартовый проект содержит счётчик как пример кода. В следующей главе вы замените его подключение приложения своей первой возможностью корзины в том же проекте. Сначала выполнять упражнение со счётчиком не нужно.

## Найдите части, которые будете менять

| Место | Что вы там делаете |
| --- | --- |
| `src/App.hs` | Подключаете сервисы, запросы, хранилище событий и веб-транспорт. |
| `src/Shop/` | Добавляете возможности приложения, которые будете писать в этом руководстве. |
| `tests/` | Описываете поведение и регулярно его проверяете. |
| `neo.json` | Задаёте сведения о проекте и объявляете дополнительные зависимости. |
| `flake.lock` и `neo-version` в `neo.json` | Сохраняете воспроизводимые версии разрешённых зависимостей. |
| `event-model.json` | Сохраняете визуальную модель, когда начнёте пользоваться IDE. |

`src/Shop/` и `event-model.json` появятся на следующих шагах; в свежем стартовом проекте их может ещё не быть. Neo генерирует низкоуровневые файлы сборки из вашей конфигурации и исходных модулей. Вносите изменения через `neo.json` и снова запускайте `neo build`, вместо того чтобы вручную поддерживать сгенерированные файлы сборки.

Сохраняйте фиксации зависимостей, которые выдаёт `neo new`. Они указывают на версию фреймворка, совместимую со стартовым проектом. Обновление — осознанное изменение проекта, для которого нужны собственные проверки сборки и поведения.

## Изучите ежедневный цикл

Эти команды вы будете запускать из корня проекта:

| Команда | Что она даёт |
| --- | --- |
| `neo build` | Проверку компилятором приложения и его подключений. |
| `neo run` | Запущенное приложение для отправки запросов. |
| `neo test` | Повторяемые проверки поведения вашего проекта. |
| `neo ide` | Визуальное рабочее пространство для изучения модели приложения. |

Пока успешная сборка — ваша проверка настройки. В следующей главе вы создадите корзину, отправите ей запрос и прочитаете результат. Так компиляция свяжется с поведением, которое можно увидеть непосредственно.

Если команда завершилась ошибкой, сохраните полный текст ошибки и обратитесь к разделу [устранение неполадок](/ru/reference/troubleshooting/). Если приложение уже существует, добавьте новую возможность в него, а не запускайте `neo new` повторно.
