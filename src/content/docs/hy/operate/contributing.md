Ավելի լավը դարձնելու համար պետք չէ հասկանալ ամբողջ շրջանակը։ Շփոթեցնող տեղադրման քայլը, բացակայող սահմանային դեպքը կամ այլևս չկոմպիլյացվող օրինակը օգտակար մեկնարկ են։ NeoHaskell սովորելու կամ ծրագիր կառուցելու Ձեր փորձը ապացույց է այն մասին, թե հաջորդ ընթերցողը որտեղ կարող է դժվարանալ։

Ներդրումը ճյուղավորվում է ծրագրի ճանապարհից։ Ձեր ծրագիրը վստահությամբ գործարկելը չի պահանջում դառնալ շրջանակի սպասարկող։

## Սկսեք սահմանափակված բարելավումից

Լավ առաջին հաղորդումը ներառում է՝ ինչ էիք փորձում անել, ամենափոքր վերարտադրումը, սպասվող վարքագիծը, փաստացի արդյունքը և համապատասխան տարբերակը։ Կիսվելուց առաջ հեռացրեք հավատարմագրերն ու մասնավոր տվյալները։

Փաստաթղթային փոփոխության դեպքում պահպանեք աստիճանական ուսուցման ուղին. նախ բացատրեք իրավիճակը, տրամադրեք ճշգրիտ օրինակ և ասեք, թե ինչպես կարող է ընթերցողը ստուգել արդյունքը։ Սխալի դեպքում ավելացրեք այն պատճառով ձախողվող ռեգրեսիայի դեպք՝ նախքան իրականացումը փոխելը։

## Գտեք սեփականատեր բաղադրիչը

| Մտահոգություն | Պահոցի տարածք |
| --- | --- |
| Լեզվի բառապաշար և ծառայության շրջանակ | `core/` |
| Գործարկվող Cart/Stock օրինակներ և HTTP ընդունման թեստեր | `testbed/` |
| Մատակարարի ինտեգրումներ | `integrations/` |
| Rust CLI և ներկառուցված տեսողական IDE | `neo/` |
| Մարդկանց համար փաստաթղթեր | `website/` |
| Ճարտարապետական որոշումներ | `docs/decisions/` |

Կարդացեք [ներդրողի README-ն](https://github.com/neohaskell/NeoHaskell/blob/main/README.md) և [հնարավորությունների քարտեզը](https://github.com/neohaskell/NeoHaskell/blob/main/codemap/README.md)։ Քարտեզը հասկացությունը կապում է դրա իրականացման և թեստերի հետ, այնպես որ փոքր ուղղումը պարտադիր չէ վերածվի պահոցի անսահման ուսումնասիրության։

## Աշխատեք պահոցի գործիքաշարով

NeoHaskell-ի պահոցի checkout-ից `./dev` հրամանները անհրաժեշտության դեպքում մտնում են ամրացված միջավայր․

```sh
./dev watch
```

Խմբագրելիս պահեք watcher-ը աշխատող։ Մեկ այլ տերմինալում․

```sh
./dev check
./dev test "EventStore" nhcore-test-service
./dev lint
```

`./dev test "EventStore" nhcore-test-service`-ը կենտրոնացված թեստային ընտրության օրինակ է։ Ընտրեք այն թեստերը, որոնք հաստատում են Ձեր փոփոխությունը. ուղղման հետ կապ չունեցող ընտրությունը ապացույց չի տալիս։ Ծառայության թեստերին կարող է պետք լինել PostgreSQL, իսկ HTTP ընդունման թեստերին՝ իրական ֆիքսված օրինակներ։ Կարգավորումը նկարագրված է ներդրողի README-ում։

Այս պահոցի հրամանները տարբերվում են `neo build` և `neo test` հրամաններից, որոնք աշխատում են ստեղծված ծրագրերի վրա։ Rust CLI-ի և IDE-ի փոփոխություններն ունեն իրենց սահմանափակված հրահանգներն ու թեստային շերտերը `neo/`-ի տակ։

## Լայն իրականացումից առաջ առաջարկեք հանրային վարքագիծը

Պահոցն օգտագործում է փոփոխության սպեցիֆիկացիաներ և կառավարվող փոփոխությունների draft pull request-ներ։ Սպեցիֆիկացիան բացատրում է խոստացված API-ի տարբերությունը և անվանում յուրաքանչյուր չափանիշ ապացուցող թեստերը։ Այդ առաջարկի սպասարկողի վերանայումը նախորդում է լայն իրականացմանը. վերջնական վերանայումը դիտարկում է իրականացված արդյունքն ու ստուգումը։

Կարդացեք [պահոցի ընթացիկ ներդրման պայմանագիրը](https://github.com/neohaskell/NeoHaskell/blob/main/AGENTS.md)՝ ճշգրիտ շրջանակի, ճյուղերի/stack-ի աշխատանքային հոսքի, վերանայման դարպասների և բացառությունների համար։ Ձախողումը կանաչ դարձնելու համար մի փոխեք առկա թեստերի ակնկալիքները։ Բացատրեք օգտատիրոջ համար տեսանելի վարքագծի փոփոխությունը և ստացեք պահանջվող սպասարկողի վերանայումը։

## Փոփոխությունը պահանջելու դեպքում խորացեք

Հիմնական ծառայության ճարտարապետությունը բաժանում է հրամանների որոշումները, իրադարձությունների պահպանումը, էության վերակառուցումը, հարցումները, տրանսպորտները և ինտեգրումները։ Մեկ հանրային իրադարձության կամ ածանցման փոփոխությունը կարող է ազդել դրանցից մի քանիսի վրա։ Հետևեք սեփականատեր թեստերին ու ճարտարապետական որոշումներին, ապա ստուգեք հանրային օրինակային ծրագիրը և տեղային միավորը։

CLI-ի փոփոխությունը կարող է փոխել նաև յուրաքանչյուր նոր ստեղծված ծրագիր։ Ներկառուցված starter-ը և starter-ի ու շրջանակի համատեղելիության ստուգումները այդ պատասխանատվության մաս են։

**Փորձեք առաջին ներդրումը․** ընտրեք մեկ շփոթեցնող պահ ուսուցման ճանապարհից կամ Ձեր ծրագրից։ Գրեք այն բացատրությունը, որն անհրաժեշտ էր Ձեզ, գտեք դրան աջակցող հանրային սկզբնաղբյուրը և խնդրեք մեկ այլ ընթերցողի հետևել դրան։ Սա կոնկրետ բարելավում է՝ նույնիսկ նախքան շրջանակի ներքին մասերին դիպչելը։
