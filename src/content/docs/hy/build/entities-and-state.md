Նոր հարցում ընդունելուց առաջ ծրագրին պետք է իմանալ համապատասխան ընթացիկ վիճակը։ Այդ վիճակի առաջացման ձևն իմանալը նաև օգնում է բացատրել անցյալի որոշումները։ NeoHaskell-ը այս կարիքները կապում է. էության ընթացիկ վիճակը կառուցվում է՝ իրադարձությունները հերթականությամբ կիրառելով։

**Էությունը** բիզնեսային օբյեկտն է, որի կանոնները պաշտպանում եք։ Այն կարող է ներկայացնել ամրագրում, փաստաթուղթ կամ հաշիվ։ Ուսումնական նախագծում դա մեկ Cart է, որը նույնացվում է UUID-ով։ Դրա վիճակն օգնում է որոշել հաջորդ հրամանը, իսկ իրադարձությունների պատմությունը գրանցում է ընդունված փոփոխությունները։

Այս էջը ենթադրում է, որ [Ձեր առաջին աշխատող շերտը](/hy/build/first-cart/) և [Cart-ի ավելացումները](/hy/build/commands-and-events/) նույն `mug-shop` նախագծում են։ Եթե ուղղակիորեն եք հասել այստեղ, բացեք Getting Started-ով ստեղծած նախագիծը և նախ օգտագործեք այդ երկու էջերի ամբողջական ֆայլերի ստուգակետերը. այս էջի ամբողջական էության ֆայլը հղվում է ավելացումների ստուգակետի `CartItem` և `ItemAdded` տիպերին։

## Ժամանակի միջով հետևեք մեկ Cart-ի

Ենթադրենք՝ մեկ Cart-ի իրադարձությունների պատմությունն է․

| Գրանցված իրադարձություն | Ստացված վիճակ |
| --- | --- |
| `CartCreated` | Cart-ն ունի նույնացուցիչ, սեփականատիրոջ նույնացուցիչ և չունի գրառումներ։ |
| `ItemAdded`, քանակ 2 | Մեկ գրառում պահում է ընտրված պահեստի նույնացուցիչը և 2 քանակը։ |
| `ItemAdded`, քանակ 1 | Ավելացվում է երկրորդ գրառում, նույնիսկ եթե այն վերաբերում է նույն պահեստին։ |

Գրառման և ընդհանուր քանակի տարբերակումը մոդելի ընտրություն է։ Ընթացիկ օրինակը կրկնվող ավելացումները չի միավորում։ Այն նաև չի հեռացնում ապրանքներ, գին չի պահում և Cart-ը վճարված չի նշում։ Դրանք առանձին բիզնեսային որոշումներ են, որոնք արժանի են իրենց փաստերին ու կանոններին։

## Որոշեք, թե որտեղ է ապրում վիճակի վարքագիծը

Աշխատեք `mug-shop` նախագծի արմատից։ `src/Shop/Cart/Event.hs`-ը տիրապետում է Cart-ի իրադարձությունների բառապաշարին և `getEventEntityId`-ին, `src/Shop/Cart/Item.hs`-ը՝ յուրաքանչյուր գրառման մեջ պահվող փոքր արժեքին, իսկ `src/Shop/Cart/Entity.hs`-ը՝ վիճակի գրառմանը, դրա սկզբնական արժեքին ու վերարտադրմանը։ `src/Shop/Cart/Core.hs`-ի տիրույթային ճակատը կրկին արտահանում է հրամանների ու հարցումների համար նախատեսված էության և իրադարձության տիպերը։

Ավելացումների էջն արդեն ասել է փոխարինել `src/Shop/Cart/Entity.hs`-ը։ Այս էջը բացատրում է, թե ինչու ունի այդ ֆայլն իր հերթականությունն ու սահմանները, ապա ցույց է տալիս ընթացիկ ամբողջական ֆայլը։ Եթե փոփոխությունն այժմ եք կիրառում, այդ ուղու ֆայլը փոխարինեք ստորև հավաքված բլոկով։ `initialState`, `update` կամ `getEventEntityId` մի տեղափոխեք այն նշիչից հետո, որը կախված է դրանցից։

## Կարդացեք վիճակն ու դրա կապակցումը

Cart-ի վիճակի գրառումը պահում է հետագա որոշումների համար անհրաժեշտ փաստերը․

```haskell
data CartEntity = CartEntity
  { cartId :: Uuid
  , ownerId :: Text
  , items :: Array CartItem
  }
```

Վերակառուցումը սկսվում է դատարկ զանգվածից և զրոյական նույնացուցիչից․

```haskell
initialState :: CartEntity
initialState = CartEntity {cartId = Uuid.nil, ownerId = "", items = Array.empty}
```

`CartCreated` դեպքը հաստատում է ինքնությունն ու սեփականատիրոջը։ `ItemAdded` դեպքը ավելացնում է հրամանով արդեն ընդունված գրառումը․

```haskell
update change cart = case change of
  CartCreated created ->
    CartEntity {cartId = created.entityId, ownerId = created.ownerId, items = Array.empty}
  ItemAdded added ->
    cart {items = cart.items |> Array.push (CartItem {stockId = added.stockId, quantity = added.quantity})}
```

Թարմացման ֆունկցիան կիրառում է ընդունված փաստը։ Վավերացումը պետք է լինի այդ փաստը գրանցելուց առաջ, իսկ արտաքին աշխատանքը՝ դրան արձագանքող ինտեգրման մեջ։ Cart-ի թարմացումը չի կանչում պահեստ, չի ուսումնասիրում այսօրվա կատալոգը և չի վերանայում, թե հարցումը պետք է ընդունվե՞ր։

`initialState`-ից և `update`-ից հետո էությունը իրադարձության տիպին միացրեք շրջանակին ուղղված `Core` ներմուծմամբ արտահանվող օգնականով․

```haskell
deriveEntity ''CartEntity ''CartEvent
```

`Event.hs`-ի `getEventEntityId`-ը պետք է ներմուծված լինի այս նշիչից առաջ։ Այս զույգը վարքագիծ է, որը պետք է վերանայեք գործակալի հետ։ Նշիչը տրամադրում է `CartEntity`-ի ու `CartEvent`-ի կապերը, JSON փոխարկումը, լռելյայն մեկնարկային արժեքը և շրջանակի վերարտադրման ու իրադարձությունների երթուղավորման օրինակները։ Այն չի պահանջում, որ էության դաշտերը աջակցեն `Show`-ին։

## Վերարտադրումը բիզնեսային սահման է

`update`-ից վավերացումը դուրս պահելը վերարտադրումը կայուն է պահում։ Եթե երեկվա Cart-ը վերակառուցելիս ուսումնասիրեիք այսօրվա ապրանքի գինը, նույն պատմությունը կարող էր տարբեր առևտրային արդյունք տալ։ Երբ գինը պետք է դառնա պատվերի համաձայնության մաս, նախագծեք համապատասխան պահին համաձայնեցված գումարն ու արժույթը գրանցող իրադարձություն։

Այդ գինը պահելը **ուսումնական նախագծի նախագծային ընդլայնում է**, ոչ թե այս Cart-ում արդեն եղած դաշտ։ Ընդհանուր դասը անցյալի որոշմանը իմաստ տվող տեղեկությունը պահպանելն է։ Ընթացիկ Decimal տիպի և դրա սահմանների համար տե՛ս [լեզվի հիմունքները](/hy/build/language-essentials/#amounts-and-money)։

Snapshot-ները կարող են նվազեցնել էությունը վերակառուցելու համար անհրաժեշտ աշխատանքը։ Դրանք արտադրողականության օժանդակ միջոց են. Ձեր սովորեցրած ու ստուգած վարքագիծը մնում է գրանցված փաստերի հերթական կիրառումը։ Պահպանման ու վերականգնման համար առանձին անդրադարձ կա [գործարկում և զարգացում](/hy/operate/) բաժնում։

## Ընթացիկ էության ամբողջական ֆայլը

Ստորև `src/Shop/Cart/Entity.hs`-ի փոխարինման հավաքված տարբերակն է՝ `mug-shop` նախագծի արմատից։ Դրա ներմուծած `CartEvent`, `CartItem` և `ItemAdded` սահմանումները ամբողջական են [հրամաններ և իրադարձություններ](/hy/build/commands-and-events/) էջում։

<!-- complete-file -->
```haskell title="src/Shop/Cart/Entity.hs"
module Shop.Cart.Entity (CartEntity (..), initialState, update) where

import Core
import Shop.Cart.Event (CartEvent (..), getEventEntityId)
import Shop.Cart.Events.CartCreated qualified as CartCreated
import Uuid qualified
import Array qualified
import Shop.Cart.Item (CartItem (..))
import Shop.Cart.Events.ItemAdded qualified as ItemAdded

data CartEntity = CartEntity
  { cartId :: Uuid
  , ownerId :: Text
  , items :: Array CartItem
  }

initialState :: CartEntity
initialState = CartEntity {cartId = Uuid.nil, ownerId = "", items = Array.empty}

update :: CartEvent -> CartEntity -> CartEntity
update change cart = case change of
  CartCreated created ->
    CartEntity {cartId = created.entityId, ownerId = created.ownerId, items = Array.empty}
  ItemAdded added ->
    cart {items = cart.items |> Array.push (CartItem {stockId = added.stockId, quantity = added.quantity})}

deriveEntity ''CartEntity ''CartEvent
```

## Վարժություն․ բացատրեք վերակառուցումը

Գործակալին տվեք այս պատմությունը․ Cart է ստեղծվում, ավելացվում է երկու բաժակ, ապա ևս երեքը։ Խնդրեք կանխատեսել և՛ գրառումների թիվը, և՛ ընդհանուր քանակը։ Այնուհետև թող նա ցուցադրի վերակառուցումը `initialState`-ից։
