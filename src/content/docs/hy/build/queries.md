Էկրանին կամ հաշվետվությանը պետք է ընթերցողի հարցի շուրջ ձևավորված տեղեկություն։ Ծրագրի ամբողջ ներքին պատմությունը ցուցադրելը այդ հարցին պատասխանելն ավելի կդժվարացներ։ Հարցումը պատրաստում է օգտակար ներկայացում՝ օրինակ վերանայման սպասող աշխատանքի կամ հարցման առաջընթացի մասին։

NeoHaskell-ի կարդալու մոդելները ներկայացումը տարանջատում են փոփոխության թույլատրելիության որոշումից։ Դա ազատություն է տալիս ձևավորել ներկայացումը, բայց ունի փոխզիջում. նոր ընդունված փոփոխությունը կարող է մի փոքր ուշ հայտնվել դրա մեջ։

Այս էջը հետևում է [Cart-ի ավելացումներին](/hy/build/commands-and-events/)։ Այդ էջը նույն Cart էությունը փոխեց, որպեսզի այն պարունակի `items`. ստորևի հարցումը կարդում է այդ վիճակը։ [Ձեր առաջին աշխատող շերտը](/hy/build/first-cart/) և ավելացումների էջը հետևեք մեկ `mug-shop` նախագծում։ Եթե այս էջին ուղղակիորեն եք հասել, նախ օգտագործեք դրանց ամբողջական ստուգակետերը, ապա ստեղծեք կամ փոխարինեք `src/Shop/Cart/Queries/CartSummary.hs`-ը այս էջի ամբողջական ֆայլով։

## Սկսեք էկրանի հարցից

Գոյություն ունեցող `CartSummary`-ը պատասխանում է․ «Ո՞ր Cart-ն է սա, ո՞ւմ է պատկանում, քանի՞ գրառում ունի և դատա՞րկ է»։ Այն չի հաղորդում ընդհանուր միավորներ կամ գներ։ Նախքան գործակալին նոր դաշտ ավելացնելու խնդրանքը որոշեք յուրաքանչյուր դաշտի իմաստը. `itemCount`-ը ներկայումս նշանակում է գրառումներ, այնպես որ հինգ բաժակի մեկ ավելացումը տալիս է մեկ հաշվարկ։

Հարցման բիզնեսային տրամաբանությունը գտնվում է `src/Shop/Cart/Queries/CartSummary.hs`-ում։ `mug-shop` նախագծի արմատից փոխարինեք այդ ֆայլը՝ նախ ուսումնասիրելով ստորև կենտրոնացված պրոյեկցիան․

```haskell
instance QueryOf CartEntity CartSummary where
  queryId cart = cart.cartId
  combine cart _previous = do
    let count = cart.items |> Array.length
    Update CartSummary
      { cartSummaryId = cart.cartId
      , ownerId = cart.ownerId
      , itemCount = count
      , isEmpty = count == 0
      }
```

`queryId`-ը որոշում է, թե այս էությունից որ ներկայացման տողն է ստացվում։ `combine`-ը ստանում է ընթացիկ էության վիճակը և առկա ներկայացումը, եթե կա։ Այստեղ ընթացիկ էությունը պարունակում է անհրաժեշտ ամեն ինչ, ուստի հին ներկայացումը չի օգտագործվում և փոխարինվում է `Update`-ով։

Մյուս արդյունքներն են `Delete`-ը, որը հեռացնում է ներկայացման տողը, և `NoOp`-ը, որը թողնում է այն անփոփոխ։ Մեկից ավելի էության տիպ կարող է մասնակցել հարցմանը։ Սկսեք մեկից, մինչև Ձեր էկրանը համակցված ներկայացման պատճառ ունենա։

## Ստացեք և գրանցեք ներկայացումը

Այս հարցման համար ֆայլը սահմանում է տվյալների գրառումը, `canAccess`-ը և `canView`-ը, ապա կանչում կանոնական օգնականը․

```haskell
deriveQuery ''CartSummary [''CartEntity]
```

Համապատասխան `QueryOf` բիզնեսային օրինակը տեղադրեք նշիչից **հետո**. այն կախված է նշիչի ստեղծած `Query` օրինակից։ Նշիչը գալիս է շրջանակին ուղղված `Core` ներմուծումից և ստեղծում ստանդարտ հարցման աջակցություն։ Ստորև ամբողջական ֆայլը պահպանում է պահանջվող ներմուծումներն ու հայտարարությունների հերթականությունը։

Ծրագրի գրանցումն արդեն առկա է առաջին շերտից `src/App.hs`-ում։ Եթե գոյություն ունեցող ծրագիրն ունի Cart-ի ծառայություն, բայց հարցման գրանցում չունի, ծառայության գրանցման կողքին ավելացրեք այս տողը․

```haskell
  |> Application.withQuery @CartSummary
```

Նշիչի ներքին անունը `CartSummary` է, իսկ HTTP URL-ը՝ `/queries/cart-summary`։ Ուսումնական հարցումը միտումնավոր թույլ է տալիս հանրային մուտք։ Մասնավոր ծրագրի տվյալները բացահայտելուց առաջ սահմանեք ու թեստավորեք [մուտքի կառավարման քաղաքականությունները](/hy/build/access-control/)։

## Ընթացիկ հարցման ամբողջական ֆայլը

Անհրաժեշտության դեպքում ստեղծեք `src/Shop/Cart/Queries` գրացուցակը, ապա նախագծի արմատից փոխարինեք `src/Shop/Cart/Queries/CartSummary.hs`-ը այս հավաքված ֆայլով․

<!-- complete-file -->
```haskell title="src/Shop/Cart/Queries/CartSummary.hs"
module Shop.Cart.Queries.CartSummary (CartSummary (..), canAccess, canView) where

import Array qualified
import Core
import Service.AccessControl (AccessError, UserClaims)
import Service.AccessControl qualified as AccessControl
import Shop.Cart.Core (CartEntity (..))

data CartSummary = CartSummary
  { cartSummaryId :: Uuid
  , ownerId :: Text
  , itemCount :: Int
  , isEmpty :: Bool
  }

canAccess :: Maybe UserClaims -> Maybe AccessError
canAccess = AccessControl.publicAccess

canView :: Maybe UserClaims -> CartSummary -> Maybe AccessError
canView = AccessControl.publicView

deriveQuery ''CartSummary [''CartEntity]

instance QueryOf CartEntity CartSummary where
  queryId cart = cart.cartId
  combine cart _previous = do
    let count = cart.items |> Array.length
    Update CartSummary
      { cartSummaryId = cart.cartId
      , ownerId = cart.ownerId
      , itemCount = count
      , isEmpty = count == 0
      }
```

`Array qualified`-ը պրոյեկցիայի օգտագործած իրական ներմուծում է. պահեք այն ֆայլը հավաքելիս։ `canAccess`-ը և `canView`-ը ծրագրի բացահայտ քաղաքականության ֆունկցիաներ են։ Այստեղ դրանք հանրային են, որպեսզի վարժությունը կարողանա Cart-ը ստուգել առանց նույնականացման. այդ հարմարությունը մասնավոր տվյալների համար խորհուրդ չէ։

## Գտեք Ձեր Cart-ը

`mug-shop` նախագծի արմատից գործարկեք ծրագիրը․

```sh
neo build
neo run
```

Ստեղծեք Cart, ավելացրեք ապրանք՝ [Cart-ի ավելացումներ](/hy/build/commands-and-events/) բաժնում նկարագրված ձևով, և `YOUR-CART-UUID`-ը փոխարինեք ստեղծման ժամանակ վերադարձված նույնացուցիչով․

```sh
curl --get http://localhost:8080/queries/cart-summary \
  --data-urlencode 'q=.cartSummaryId == "YOUR-CART-UUID"' \
  --data-urlencode 'limit=10' \
  --data-urlencode 'offset=0'
```

Սպասեք էջի օբյեկտի։ Դրա `items` զանգվածը պրոյեկցիայի հասնելուց հետո պարունակում է համապատասխան ամփոփումը։ `total`-ը արտացոլում է հասանելի և զտված արդյունքների քանակը, `hasMore`-ը ասում է՝ արդյոք համապատասխանող այլ արդյունքներ կան, իսկ `effectiveLimit`-ը հաղորդում է կիրառված էջի սահմանը։

Լռելյայն էջի չափը 100 է, offset-ը՝ զրո, իսկ բացարձակ առավելագույն չափը՝ 1000։ Հարցումը կարող է ավելի ցածր սահմանել՝ նշիչից առաջ սահմանելով `maxResults :: Int`։ Էջերով առաջ շարժվելիս հաճախորդները պետք է օգտագործեն վերադարձված `effectiveLimit`-ը։

Ընթացիկ NeoQL-ն աջակցում է դաշտի հասանելիությանը և տողային կամ թվային բառացի արժեքներով հավասարությանը։ Այն ընդհանուր SQL լեզու չէ. մի հորինեք միացումներ, տեսակավորում, համակցված պայմաններ կամ Boolean բառացի արժեքների համեմատություններ։ Անվավեր շարահյուսությունը տալիս է վերլուծման սխալ, իսկ արտահայտությունները սահմանափակված են 500 նիշով։

## Խուսափեք մոլորեցնող բեռնման էկրանից

Ընդունված հրամանից հետո ցույց տվեք հստակ սպասման վիճակ, մինչ ներկայացումը հասնում է վերջին փոփոխությանը։ Կարդալը կրկին փորձեք սահմանափակված քանակով և օգտակար ձախողման վիճակով։ Դատարկ առաջին պատասխանը հրամանի ձախողման ապացույց չէ։ Ավելացումը կրկին ուղարկելը միայն այն պատճառով, որ ամփոփումը չի հայտնվել, կարող է այն կրկնակի ավելացնել։

## Վարժություն․ Cart-ի ցուցիչը

Միջերեսն ասում է «5 ապրանք», բայց հաճախորդը հինգ բաժակի մեկ ավելացում է կատարել։ Ցուցիչը պե՞տք է ցույց տա մեկ, թե՞ հինգ։ Ձևակերպեք իմաստը, ապա խնդրեք գործակալին նշել, թե ինչը պետք է փոխվի։
