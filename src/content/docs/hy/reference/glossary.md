Օգտագործեք այս էջը, երբ որևէ տերմին խանգարում է հասկանալ ծրագրի այն վարքագիծը, որը փորձում եք ուսումնասիրել։ Սահմանումները կիրառվում են տարբեր տիրույթներում։ Կրկնվող էլեկտրոնային առևտրի ուսումնական նախագծի օրինակները դրանց մի մասը կոնկրետ են դարձնում, իսկ հղումները տանում են ավելի խոր բացատրությունների։

| Տերմին | Իմաստ և օրինակ | Կարդալ ավելին |
| --- | --- | --- |
| Command (Հրաման) | Հարցում, օրինակ՝ երկու բաժակ ավելացնել զամբյուղին. այն կարող է մերժվել | [Հրամաններ և իրադարձություններ](/hy/build/commands-and-events/) |
| Event (Իրադարձություն) | Ընդունված փաստ, օրինակ՝ ապրանքն ավելացվել է | [Հրամաններ և իրադարձություններ](/hy/build/commands-and-events/) |
| Entity (Էություն) | Բիզնեսային օբյեկտ, որի վիճակը տեղեկացնում է որոշումներին, օրինակ՝ կոնկրետ զամբյուղ | [Էություններ և վիճակ](/hy/build/entities-and-state/) |
| Event stream (Իրադարձությունների հոսք) | Էությանը պատկանող կարգավորված պատմություն | [Պահպանում](/hy/operate/persistence/) |
| Event sourcing (Իրադարձությունների աղբյուրավորում) | Ընդունված փաստերը պահել և դրանցից վիճակը վերակառուցել | [Իրադարձությունների մոդելավորում](/hy/start/event-modeling/) |
| Event modeling (Իրադարձությունների մոդելավորում) | Նկարագրել հարցումների, փաստերի, ներկայացումների և արտաքին գործողությունների կապը | [Իրադարձությունների մոդելավորում](/hy/start/event-modeling/) |
| Decider (Որոշիչ) | Տրամաբանություն, որը ընթացիկ վիճակով ընդունում կամ մերժում է հարցումը | [Հրամաններ և իրադարձություններ](/hy/build/commands-and-events/) |
| Query / read model / projection (Հարցում / կարդալու մոդել / պրոյեկցիա) | Կարդալու համար պատրաստված տեղեկություն, օրինակ՝ զամբյուղի ամփոփում | [Հարցումներ](/hy/build/queries/) |
| CQRS | Համակարգը փոխող հարցումները պատրաստված տեղեկության ընթերցումից տարանջատելը | [Հարցումներ](/hy/build/queries/) |
| Eventual consistency (Վերջնական համահունչություն) | Կարդալու ներկայացումը կարող է կարճ ժամանակ հետ մնալ ընդունված փոփոխությունից | [Հարցումներ](/hy/build/queries/) |
| Replay (Վերարտադրում) | Պահված իրադարձությունները կրկին կիրառել՝ վիճակ կամ ներկայացումներ վերակառուցելու համար | [Վերականգնում](/hy/operate/recovery/) |
| Snapshot (Պատկեր) | Քեշավորված վիճակ, որը նվազեցնում է նորից կարդալու պատմության ծավալը | [Արտադրողականություն](/hy/operate/performance/) |
| Integration (Ինտեգրում) | Ծրագրի մեկ այլ մասի կամ արտաքին ծառայության հետ բացահայտ կապ | [Ինտեգրումներ](/hy/connect/) |
| Outbound (Ելքային) | Ծրագրի ընդունված իրադարձություններով գործարկվող աշխատանք, օրինակ՝ էլեկտրոնային նամակի պատրաստում | [Ինտեգրման կյանքի ցիկլ](/hy/connect/) |
| Inbound (Մուտքային) | Ծրագրին աշխատանք ուղարկող ազդակ, օրինակ՝ ժամաչափ | [Ժամաչափեր](/hy/connect/timers/) |
| Idempotency (Կրկնելիության անփոփոխություն) | Հարցումը կրկնելը ունի նույն նախատեսված բիզնեսային ազդեցությունը, ինչ մեկ անգամ կատարելը | [HTTP և վճարումներ](/hy/connect/http-and-payments/) |
| Correlation identifier (Հարաբերակցության նույնացուցիչ) | Հարցումը հետագա մատակարարի պատասխաններին կամ բիզնեսային փաստերին կապող արժեք | [Աշխատանքային հոսքեր](/hy/connect/workflows/) |
| Optimistic concurrency (Լավատեսական համաժամանակություն) | Հայտնաբերել, որ որոշում կայացնելիս վիճակը փոխվել է, և մշակել հակասությունը | [Պահեստ և վճարում](/hy/build/stock-and-checkout/) |
| Authentication (Նույնականացում) | Հարցումը կատարողին նույնականացնել | [Մուտքի կառավարում](/hy/build/access-control/) |
| Authorization (Լիազորում) | Որոշել, թե այդ մարդն ինչ կարող է անել կամ տեսնել | [Մուտքի կառավարում](/hy/build/access-control/) |
| Schema (Սխեմա) | Տվյալների սպասվող ձևի նկարագրություն | [HTTP և frontend](/hy/build/http-and-frontend/) |
| Transport (Տրանսպորտ) | Հարցումների ու պատասխանների՝ ծրագրի սահմանը հատելու եղանակը, օրինակ՝ HTTP | [HTTP և frontend](/hy/build/http-and-frontend/) |
| Liveness (Կենդանություն) | Արդյոք գործող HTTP գործընթացը պատասխանում է | [Տեղակայում](/hy/operate/deployment/) |
| Readiness (Պատրաստականություն) | Արդյոք գրանցված հարցումների պրոյեկցիաները հասել են վերջին փոփոխությանը, որպեսզի այս տարբերակը կարողանա երթևեկություն սպասարկել | [Տեղակայում](/hy/operate/deployment/) |
| Business invariant (Բիզնեսային ինվարիանտ) | Ճշմարիտ մնալու պարտադիր կանոն, օրինակ՝ բացասական քանակը մերժելը | [Թեստավորում](/hy/build/testing/) |

## Երեք տարբերակում, որոնք արժե պահպանել

**Հարցումը փաստ չէ։** Էլեկտրոնային առևտրի օրինակում «Գանձել հաճախորդից» հարցում է։ Հաստատված վճարումը տեղի ունեցածի ապացույց է։ Ժամանակի ավարտը անորոշություն է թողնում. այն չի հաստատում, որ գանձում չի եղել։

**Վիճակը յուրաքանչյուր ընթերցողի ներկայացում չէ։** Էության վիճակն աջակցում է որոշումներին։ Տարբեր ընթերցողներին կարող են պետք լինել տարբեր ներկայացումներ ու մուտքի կանոններ։ Էլեկտրոնային առևտրի օրինակում հաճախորդի ամփոփումն ու վաճառողի հաշվետվությունը տարբեր նպատակներ են սպասարկում։

**Անցած ստուգումը շրջանակ ունի։** Կոմպիլյացիան, մոդելի վավերացումը, թեստերը և մատակարարի sandbox-ի ստուգումները տարբեր հարցերի են պատասխանում։ [Վստահության գլուխը](/hy/start/trusting-your-agent/) բացատրում է, թե ինչպես դրանք համադրել՝ Ձեր գործակալի աշխատանքն ընդունելիս։
