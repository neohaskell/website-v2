Պետք չէ սովորել յուրաքանչյուր մոդուլը՝ նախքան NeoHaskell օգտագործելը։ Սկսեք այն առաջադրանքից, որը պետք է կատարի ծրագիրը, գտեք համապատասխան հասկացությունը և խորացեք, երբ ընթացիկ առաջադրանքը դա պահանջի։ Այս քարտեզը նաև օգնում է գնահատողին շրջանակի կառուցվածքային տարրերը տարբերել այն ծրագրային հնարավորություններից, որոնք թիմը պետք է իրականացնի։

Շարունակեք `neo new`-ով ստեղծված ծրագրում։ Ուղղորդվող նախագծում Cart-ի և Stock-ի կոդը գտնվում է `src/Shop/`-ի տակ։ Ստորևի հղումները սովորեցնում են, թե ինչպես օգտագործել յուրաքանչյուր հնարավորություն այնտեղ, իսկ հանրային իրականացման հղումները տրամադրում են օժանդակ ապացույց։

## Մոդելավորեք և բացահայտեք ծրագրի վարքագիծը

| Կարիք | Հնարավորություն | Որտեղ շարունակել |
| --- | --- | --- |
| Որոշել՝ թույլատրելի՞ է պահանջված փոփոխությունը | Հրամաններ և `Decider` | [Կառուցել ծրագիր](/hy/build/) |
| Պահպանել ընդունված փաստերը | Իրադարձություններ և իրադարձությունների պահոցներ | [Պահպանում](/hy/operate/persistence/) |
| Վերակառուցել էության ընթացիկ վիճակը | Էություններ և snapshot-cache միջերեսներ | [Կառուցել ծրագիր](/hy/build/) |
| Տարբեր ընթերցողների համար ներկայացումներ պատրաստել | Հարցումներ, հարցումների օբյեկտների պահոցներ, էջավորում | [Կառուցել ծրագիր](/hy/build/) |
| Մատուցել հրամաններ և հարցումներ | HTTP տրանսպորտ, JSON, schema/OpenAPI | [Կառուցել ծրագիր](/hy/build/) |
| Կապել ծրագիրը | `Application` և ծառայության սահմանումներ | [Սկսել](/hy/getting-started/) |
| Սահմանափակել գործողություններն ու կարդալը | Նույնականացում, հրամանների քաղաքականություններ, հարցումների մուտքի վերահսկումներ | [Անվտանգություն](/hy/operate/security/) |

Հրամանները, իրադարձությունները և հարցումները ունեն ածանցման նշիչներ, որոնք ստեղծում են շրջանակի կապակցումը։ Էությունները բացահայտ տրամադրում են իրենց սկզբնական վիճակն ու թարմացման վարքագիծը։ Նախ սովորեք հայեցակարգային դերը, հետո ուսումնասիրեք այդ գեներացման աշխատանքը։

## Ծրագիրը կապեք այլ համակարգերի հետ

| Կարիք | Հնարավորություն | Սահման |
| --- | --- | --- |
| Արձագանքել ընդունված փաստին | Ելքային ինտեգրման գործարկման միջավայր | Սահմանեք բիզնեսային հաջորդող աշխատանքն ու ձախողման արդյունքը |
| Ստանալ արտաքին ազդակներ կամ ժամանակավորված աշխատանք | Մուտքային ինտեգրումներ | Մուտքը վերածեք բացահայտ հրամանի |
| Կանչել մատակարարի | HTTP հաճախորդ և ինտեգրման հարցման/պատասխանի տիպեր | Մատակարարին հատուկ պայմանագրերը դեռ իրականացման ու թեստերի կարիք ունեն |
| Կապել օգտատիրոջ մատակարարի հաշիվը | OAuth2 համաձայնություն, callback-ներ և գաղտնիքների պահեստավորում | [Մատակարարի հաշիվներ](/hy/connect/provider-accounts/) |
| Ուղարկել էլեկտրոնային նամակ | Brevo և Azure Communication Services ինտեգրումներ | Պահանջում է մատակարարի կազմաձևում և առաքման ստուգում |
| Ավելացնել լեզվային մոդելի հնարավորություններ | OpenRouter, AzureAI և գործակալի/գործիքների ինտեգրումներ | Սահմանեք թույլատրելի գործողություններն ու արդյունքների ստուգման ձևը |
| Մշակել փաստաթղթեր | Ֆայլերի վերբեռնում, PDF, OCR և համապատասխան մատակարարի ինտեգրումներ | Պահպանեք բայթերը, պաշտպանեք մուտքը և մշակեք արդյունահանման ձախողումները |
| Մշակել աուդիո | Աուդիոյի/արտագրման ինտեգրումներ | Արտաքին արդյունքը դիտարկեք որպես սխալվող մուտք |

Այս թեմաների համար հետևեք [ինտեգրումներին](/hy/connect/)։ Էլեկտրոնային առևտրի ուսումնական նախագիծը ցույց է տալիս դրանց համադրումը, բայց հնարավորությունները կիրառելի են տարբեր տիրույթներում։ Ընդհանուր HTTP հաճախորդին դեռ պետք է մատակարարի պայմանագիր. օրինակ՝ այն պատրաստի վճարման կամ առաքման ադապտեր չէ։ Տիրույթին հատուկ կանոններն ու աշխատանքային հոսքերը մնում են ծրագրի աշխատանք, եթե կոնկրետ իրականացում չի տրամադրում դրանք։

## Անհրաժեշտության դեպքում օգտագործեք լեզվի բառապաշարը

Հիմնական գրադարանը ներառում է `Text`, `Array`, `Map`, `Maybe`, `Result`, `Task`, նույնացուցիչներ, ամսաթվեր, մատյանագրում և հարակից պարզունակներ։ Հատկանիշները նկարագրում են տիպերի միջև վերօգտագործելի գործողություններ։ JSON/schema մոդուլները տիպավորված տվյալները կապում են արտաքին ներկայացումների հետ։

Համակարգային մոդուլները տրամադրում են ֆայլեր, ուղիներ, գրացուցակներ, միջավայրի հասանելիություն, ժամանակ և ենթագործընթացներ։ Համաժամանակության մոդուլները տրամադրում են առաջադրանքներ, կապուղիներ, lock-եր և համօգտագործվող փոփոխականներ։ Սրանք կոնկրետ կարիքի մեխանիզմներ են. համաժամանակություն ներմուծելը ինքնաբերաբար չի դարձնում բիզնեսային գործողությունը ատոմական ծառայությունների միջև։

Լեզվին հարակից մոդուլները ներառում են տասնորդական թվաբանություն, վերլուծում և NeoQL գործիքներ։ Դրանց գոյությունը ամբողջական փող/հարկերի մոդելի կամ անսահմանափակ բիզնեսային հաշվետվության լեզվի խոստում չէ։ Ձեր իրական պահանջի համար ընտրեք աջակցվող գործողությունը, ներկայացումը և սահմանային թեստերը։

Օգտագործեք [լեզվի հիմունքները](/hy/build/language-essentials/) և [բառարանը](/hy/reference/glossary/)՝ անծանոթ բառապաշարի հայտնվելուն զուգահեռ։

## Կառուցեք, ուսումնասիրեք, ստուգեք և շահագործեք

| Կարիք | Հնարավորություն | Փաստաթուղթ |
| --- | --- | --- |
| Ստեղծել ու աշխատել նախագծի վրա | Neo CLI | [CLI տեղեկատու](/hy/reference/cli/) |
| Տեսողականորեն հասկանալ մոդելը | Ներկառուցված Neo IDE | [Տեսողական IDE](/hy/getting-started/visual-ide/) |
| Ստեղծել վարքագծային ապացույց | Թեստային DSL, ծրագրի սցենարներ, Hurl ընդունման թեստեր | [Թեստավորում](/hy/build/testing/) |
| Միացնել կայուն պահոցները | Postgres ենթակառուցվածք | [Պահպանում](/hy/operate/persistence/) |
| Գործարկել և փոխել ծրագիրը | Ստուգումներ, մատյանագրում, վերարտադրում և համատեղելիության գործելակերպեր | [Գործարկել ու զարգացնել](/hy/operate/) |
| Բարելավել շրջանակը | Հանրային օրինակային ծրագիր, պահոցի գործիքներ, ճարտարապետական որոշումներ | [Ներդրում](/hy/operate/contributing/) |

Սկզբնաղբյուրի մանրամասների համար պահոցի [հնարավորությունների քարտեզը](https://github.com/neohaskell/NeoHaskell/blob/main/codemap/capabilities.yaml) նույնացնում է իրականացման սեփականությունն ու թեստերը։ Թվարկված հնարավորությունն ասում է, թե որտեղ ուսումնասիրել, իսկ կոնկրետ օրինակն ու թեստը հաստատում են այն վարքագիծը, որի վրա կարող եք հենվել։

Կենտրոնացված բաղադրատոմսերի համար թերթեք [գործնական ուղեցույցները](/hy/guides/)։
