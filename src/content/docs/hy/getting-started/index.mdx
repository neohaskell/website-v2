Ձեր առաջին փուլը սեփական նախագիծն է։ Այն կստեղծեք `neo`՝ NeoHaskell-ի հրամանի տողի գործիքի միջոցով, ապա կզարգացնեք հաջորդ գլուխներում։ Նույն գրացուցակը կպահի Ձեր կոդը, թեստերը, կազմաձևումը և տեսողական մոդելը։

Ուսումնական նախագիծը կոչում ենք `mug-shop`։ Սա փոքր ծրագիր է, որը պատրաստվում եք կառուցել։ Կարող եք ընտրել մեկ այլ անուն և `mug-shop` նշված տեղերում օգտագործել այդ գրացուցակը։

## Պատրաստեք գործիքները

Օգտագործեք macOS կամ Linux, իսկ Windows-ում աշխատեք WSL2-ի ներսում։ Տեղադրեք Git-ը և [Nix-ը Ձեր օպերացիոն համակարգի համար](https://nixos.org/download/)։ Nix-ը տրամադրում է Ձեր նախագծի ընտրած կոմպիլյատորն ու կառուցման կախվածությունները։ GHC կամ Cabal առանձին տեղադրելու կարիք չկա։

Նոր տերմինալում ստուգեք, որ երկու հրամաններն էլ հասանելի են․

```sh
git --version
nix --version
```

Neo-ն օգտագործում է Nix flakes։ Եթե Ձեր Nix-ի տեղադրումը դրանք միացված չունի, ավելացրեք այս տողը `~/.config/nix/nix.conf`-ում՝ պահպանելով առկա կարգավորումները․

```ini
experimental-features = nix-command flakes
```

## Տեղադրեք Neo-ն

Ներբեռնեք Ձեր համակարգչի համար նախատեսված գործարկվող ֆայլը [Neo-ի թողարկումներից](https://github.com/neohaskell/NeoHaskell/releases/latest)։

:::note[Տարբերակի պահանջ]

Այս օրինակները պահանջում են Neo-ի այն թողարկումը, որի մեկնարկային շրջանակի ամրակը `Core`-ի միջոցով արտահանում է բոլոր հինգ `derive…` օգնականները՝ ներառյալ `deriveEntity`-ը, և օգտագործում է համապատասխան Neo կոմպիլյատորի նախադրվածը։ `neo new`-ից հետո պահեք ստեղծված `neo-version` ամրակը. եթե մեկնարկային նախագիծը այս օգնականները չի տրամադրում, տեղադրեք համապատասխան շրջանակի ամրակով թողարկում՝ սկզբնաղբյուր ֆայլերը փոխելուց առաջ։ Պետք չէ լեզվի կարգավորումներ ավելացնել Ձեր սկզբնաղբյուր ֆայլերին։

:::

| Համակարգիչ | Ներբեռնում |
| --- | --- |
| macOS, Apple silicon | `neo-aarch64-apple-darwin` |
| macOS, Intel | `neo-x86_64-apple-darwin` |
| Linux կամ WSL2, Intel/AMD 64-bit | `neo-x86_64-unknown-linux-gnu` |
| Linux, ARM 64-bit | `neo-aarch64-unknown-linux-gnu` |

Օրինակ՝ Apple silicon-ով Mac-ում․

```sh
mkdir -p "$HOME/.local/bin"
curl -fL https://github.com/neohaskell/NeoHaskell/releases/latest/download/neo-aarch64-apple-darwin -o "$HOME/.local/bin/neo"
chmod +x "$HOME/.local/bin/neo"
export PATH="$HOME/.local/bin:$PATH"
neo --version
```

Մեկ այլ հարթակի համար ներբեռնման URL-ի վերջնական ֆայլի անունը փոխարինեք աղյուսակի համապատասխան անունով։ Պահեք նպատակակետի ֆայլի անունը `neo`։ `export PATH` տողը ավելացրեք Ձեր shell-ի գործարկման ֆայլին (`~/.zshrc` zsh-ի կամ `~/.bashrc` bash-ի համար), որպեսզի Neo-ն հասանելի լինի նաև ապագա տերմինալներում։ Թողարկումը ներառում է `SHA256SUMS`, եթե ցանկանում եք ստուգել ներբեռնված ֆայլի checksum-ը։

Հրամանը տպում է տեղադրված Neo-ի տարբերակը։ `command -v neo`-ն ցույց է տալիս, թե որ գործարկվող ֆայլն է գտել Ձեր shell-ը։ Արդիականացնելիս ստուգեք երկուսն էլ, որպեսզի ավելի հին տեղադրումը Ձեր `PATH`-ում առաջնահերթ չլինի։

## Ստեղծեք ծրագիրը

Այն գրացուցակից, որտեղ պահում եք նախագծերը․

```sh
neo new mug-shop
cd mug-shop
neo build
```

Ընդունեք նախագծի տվյալները կամ ընտրեք Ձեր սեփականը, երբ Neo-ն հարցնի։ `neo new`-ը ստեղծում է փոքր մեկնարկային ծրագիր, թեստերի հավաքածու և ամրացված կախվածություններ։ `neo build`-ը կոմպիլյացնում է այն։ Առաջին կառուցումը կարող է ավելի երկար տևել, քանի դեռ կախվածությունները ներբեռնվում կամ կառուցվում են. հետագա կառուցումները կրկին օգտագործում են այդ աշխատանքը։ Nix-ը կարող է հարցնել՝ վստահո՞ւմ եք նախագծի հայտարարած երկուական քեշերին։

Մեկնարկային նախագիծը որպես օրինակ ներառում է հաշվիչ։ Հաջորդ գլխում այս նույն նախագծի ներսում դրա ծրագրային կապակցումը կփոխարինեք Ձեր առաջին զամբյուղի հնարավորությամբ։ Նախ պետք չէ հաշվիչի վարժություն ավարտել։

## Գտեք այն մասերը, որոնք կփոխեք

| Տեղադրություն | Ինչ եք անում այնտեղ |
| --- | --- |
| `src/App.hs` | Միացնում եք Ձեր ծառայությունները, հարցումները, իրադարձությունների պահոցը և վեբ տրանսպորտը։ |
| `src/Shop/` | Ավելացնում եք այս ուղեցույցում գրելիք ծրագրային հնարավորությունները։ |
| `tests/` | Նկարագրում եք վարքագիծը և կրկնաբար ստուգում այն։ |
| `neo.json` | Սահմանում եք նախագծի տվյալները և հայտարարում լրացուցիչ կախվածությունները։ |
| `flake.lock` և `neo.json`-ի `neo-version`-ը | Պահում եք լուծված կախվածությունների վերարտադրելի տարբերակները։ |
| `event-model.json` | Պահում եք տեսողական մոդելը, երբ սկսում եք օգտագործել IDE-ն։ |

`src/Shop/`-ը և `event-model.json`-ը կհայտնվեն հաջորդ քայլերում. դրանք թարմ մեկնարկային նախագծում պարտադիր չէ, որ գոյություն ունենան։ Neo-ն Ձեր կազմաձևումից և սկզբնաղբյուրի մոդուլներից ստեղծում է կառուցման ցածր մակարդակի ֆայլերը։ Փոփոխությունները կատարեք `neo.json`-ի միջոցով և կրկին գործարկեք `neo build`՝ կառուցման ստեղծված ֆայլերը ձեռքով պահպանելու փոխարեն։

Պահեք `neo new`-ի տրամադրած կախվածությունների ամրակները։ Դրանք նույնացնում են մեկնարկային նախագծի հետ համատեղելի շրջանակի վերանայումը։ Արդիականացումը գիտակցված նախագծային փոփոխություն է՝ իր կառուցման և վարքագծի ստուգումներով։

## Սովորեք ամենօրյա շրջանը

Այս հրամանները շարունակաբար կօգտագործեք նախագծի արմատից․

| Հրաման | Ինչ է տալիս |
| --- | --- |
| `neo build` | Ծրագրի և դրա կապակցումների կոմպիլյատորի ստուգում։ |
| `neo run` | Գործող ծրագիր՝ հարցումներ փորձելու համար։ |
| `neo test` | Ձեր նախագծի կրկնելի վարքագծի ստուգումները։ |
| `neo ide` | Տեսողական աշխատանքային տարածք՝ ծրագրի մոդելն ուսումնասիրելու համար։ |

Առայժմ հաջող կառուցումը կարգավորման ստուգումն է։ Հաջորդ գլխում կստեղծեք զամբյուղ, հարցում կուղարկեք դրան և հետ կկարդաք արդյունքը։ Դա կոմպիլյացիան կապում է իրականում ստուգելի վարքագծի հետ։

Եթե հրամանը ձախողվի, պահեք դրա ամբողջական սխալը և օգտագործեք [խնդիրների վերացումը](/hy/reference/troubleshooting/)։ Եթե արդեն ունեք ծրագիր, նորից `neo new` գործարկելու փոխարեն նոր հնարավորությունը կիրառեք այնտեղ։

Հաջորդը՝ [կառուցեք Ձեր առաջին զամբյուղը](/hy/build/first-cart/)։
