言語マニュアルを暗記しなくても、アプリケーションの振る舞いを指示できます。それでも、少しの語彙があればエージェントの提案を調べ、より鋭い質問をできます。この値は存在しないことがあるか？この操作は失敗するか？この関数は決定を行うのか、それとも外部アクションを実行するのか？

このページは、読むときの補助として使います。例は EC の練習用プロジェクトと、よくあるデータ処理作業から取っています。設定済みの NeoHaskell モジュール向けの小さな式または部分関数であり、インストールする別のアプリケーションではありません。

## パイプラインを左から右へ読む

NeoHaskell では、`|>` を使って名前の付いたステップに値を渡すことがよくあります。

```haskell
cart.items |> Array.length
```

これは「カートのエントリを取り出し、その数を数える」という意味です。この式は `src/Shop/Cart/Queries/CartSummary.hs` で使いました。`Array.length` のような修飾付きの名前は、どのモジュールが操作を提供するかを示します。

`Core` がデフォルトの語彙を提供します。ここでの説明用抜粋ではモジュールヘッダーと import リストを省略しています。ダウンロード可能なチェックポイントには完全なファイルがあります。Neo が言語設定を管理するため、アプリケーションファイルに言語プラグマは必要ありません。レコードには名前付きフィールドがあり、`cart.ownerId` はその 1 つを読み、`cart {ownerId = newOwner}` は更新されたレコード値を生成します。その値を生成しただけでは、イベントは永続化されません。

## 不在、失敗、作業を区別する

| 型 | 明示する問い | 例 |
| --- | --- | --- |
| `Maybe value` | 値は存在するか？ | カート検索は `Nothing` または `Just cart` を返せる。 |
| `Result error value` | 計算は成功したか？ | JSON デコードは `Err message` または `Ok value` を返せる。 |
| `Task error value` | どんな作業が結果を生み、どう失敗するか？ | ファイルの読み込みや HTTP リクエスト。 |
| `Decision event` | どのビジネス上の事実を受け入れるべきか？ | 商品追加を受け入れるか、数量を拒否する。 |

`case` で扱う可能性に名前を付けます。この**適応した部分ヘルパー**は、純粋な入力チェックを示します。

```haskell
validateQuantity :: Int -> Result Text Int
validateQuantity quantity =
  if quantity > 0
    then Ok quantity
    else Err "Quantity must be positive"
```

`Task.yield` は成功したタスク結果を生成し、`Task.throw` はタスクエラーを生成します。`Task.mapError` は境界でエラー型を変換し、`Task.asResult` はエラーを値として調べられるようにします。コードを続行させるためだけに意味のある失敗をデフォルト値へ置き換えないでください。呼び出し元はアクションが完了しなかったことを知る必要があるかもしれません。

`do` はステップを順番に実行し、`<-` はステップの結果を受け取り、`let` はローカル値に名前を付けます。そのため、アプリケーションのオーケストレーションを、すべての分岐を 1 つの大きな関数に押し込まず上から下へ読めます。

## コレクションと識別子

順序付きの値には `Array` を、識別子でキー付けする値には `Map` を使います。`Array.map` はエントリを変換し、`Array.takeIf` は一致するエントリを残し、`Array.reduce` はエントリを結果にまとめます。キーが存在しない可能性があるため、`Map.get` は `Maybe` を返します。

`Uuid.fromText` も `Maybe` を返します。URL から来たテキストが有効な識別子だとは限らないからです。ID の解析に成功すると形式は確定しますが、呼び出し元が対応する記録へアクセスできることまでは確定しません。

通常の文字列型は `Text` です。`[fmt|Cart #{cartId}|]` のようなフォーマットは、補間を読みやすく保ちます。名前付きのドメイン型とレコードフィールドを使い、エージェントの実装がイベントモデルの区別を保つようにします。

## 金額と通貨

数値には、単位、境界、丸め規則を定義する必要があります。練習用プロジェクトの金額は役に立つ例です。価格には金額と通貨の両方が必要です。`Decimal` 型は小数点以下 4 桁の固定小数点ストレージを提供します。JSON には、`"12.5000"` のような文字列としてシリアライズされます。

これらの**ソースに基づく式**は、構築とフォーマットを示します。

```haskell
Decimal.fromCents 1250 |> Decimal.formatDecimal
-- "12.5000"

Decimal.divide (Decimal.fromCents 1250) Decimal.zero
-- Nothing
```

小数点以下 2 桁の補助単位を持つ通貨なら、`fromCents` は整数の補助単位から構築します。`toCents` はより細かい精度を切り捨てます。暗黙の丸めポリシーではありません。`roundTo2` は明示的な操作で、ゼロ除算には値がないため除算は `Maybe` を返します。

実装は `Int64` を保存するため、金額には境界があります。現在のテキストパーサーは浮動小数点への変換を通過するため、任意精度の金融パーサーだと説明してはいけません。通貨ポリシーに収まるなら、検証済みの整数補助単位を優先し、丸めと最大金額をテストします。`Decimal` が通貨を付加したり、税のルールを決めたりすることはありません。

## トレイトとマーカーが提供するもの

トレイトは、型がサポートする振る舞いを記述します。`Mappable` は含まれる値の変換を許可し、`Default` は開始値を提供し、シリアライズのトレイトは値と JSON をつなぎます。関数シグネチャの制約は、必要な振る舞いを示します。

`deriveEvent`、`deriveCommand`、`deriveEntity`、`deriveQuery`、`deriveOutboundIntegration` のヘルパーは `Core` から提供され、よくあるインスタンスを生成します。繰り返しの配線を減らしながら、決定、状態更新、プロジェクションは確認できるビジネスロジックとして残ります。[コマンドとイベント](/ja/build/commands-and-events/)で宣言の順番を確認し、クエリ固有の順番は[クエリ](/ja/build/queries/#derive-and-register-the-view)で確認してください。

## 演習：「安全な」ヘルパーをレビューする

練習用プロジェクトで、エージェントが無効な数量を解析し、リクエストが必ず成功するように別の値へ置き換えます。それが要求された振る舞いに反する理由を説明し、観測できる確認方法を提案します。

<details>
<summary>考え方と確認の例</summary>

マグカップ 1 個は有効な数量ですが、顧客が要求した数量とは限りません。無効な入力をエラーとして保持し、インターフェースから修正を求められるようにします。通常の正の値、不正な形式、0、演習のポリシーが許す最大数量を確認します。より小さい数値や金額表現への変換も、限界値でテストします。型チェックはカテゴリーの区別に役立ちますが、受け入れ可能なビジネス上のデフォルト値は選びません。

</details>
