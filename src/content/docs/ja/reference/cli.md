Neo CLI は NeoHaskell プロジェクトの作成、ビルド、テスト、調査を助けます。今すぐの目的に合うコマンドを使います。視覚的な IDE には、同じプロジェクトを理解する別の方法があります。

プロジェクトコマンドは `neo.json` があるディレクトリから実行します。`neo --help` またはコマンドの `--help` で、インストールされたバイナリ自身のヘルプを表示します。このページは、[セットアップ](/ja/getting-started/)で使う Neo 0.10.0 について説明します。古いリリースがインストールされている場合は異なることがあります。

## 共通フラグ

| フラグ | 効果 |
| --- | --- |
| `-v`、`--verbose` | デバッグレベルの CLI 出力を有効にする |
| `--ci` | 対話プロンプト、アニメーション、色を無効にする |
| `--help` | ヘルプを表示する |
| `--version` | バージョンを表示する |

`--ci` は繰り返し可能なスクリプトで役立ちます。ローカルテストを本番デプロイに変えるものではありません。

## 作成、ビルド、実行、テスト

この手順では、繰り返し使う練習用プロジェクトの名前 `mug-shop` を使います。自分のプロジェクト名に置き換えます。コマンドは同じように動きます。

```sh
neo --ci new mug-shop
cd mug-shop
neo build
neo run
```

`neo run` は Ctrl-C で停止するまで提供を続けます。テストを実行する前に停止してください。`neo test` は独自のアプリケーションプロセスを起動するためです。

```sh
neo test
```

| コマンド | オプション | 振る舞い |
| --- | --- | --- |
| `neo new [project_name]` | `--library` | 組み込みスターターから雛形を作る。CI モードでは名前が必要。ライブラリではランチャーと実行ファイルの stanza を省略する。 |
| `neo build` | `--watch`、`--skip-lock-check` | 設定を照合してビルドする。watch は GHCi のフィードバックを使い、skip はビルドのロック確認だけを迂回する。 |
| `neo run` | `--watch` | 照合、ビルド、実行を行う。watch は変更時に再ビルド・再起動する。 |
| `neo test` | `--watch` | プロジェクトのユニットテストを実行し、その後に見つかった Hurl HTTP テストを実行する。 |

`build`、`run`、`test` は `neo.json` から管理対象のビルドファイルを再生成し、`src/` と `tests/` の下にあるモジュールを見つけます。`Shop.Cart` と `Shop.Stock` のモジュールはアプリケーション内に残り、CLI がビルドへの組み込みを処理します。

Hurl テストがある場合、test コマンドはアプリケーションを起動し、実行前に `127.0.0.1:8080` で HTTP 応答を待ちます。この待機は任意の HTTP 応答を受け入れ、`/ready` のプロジェクション契約を待ちません。プロジェクトのテストポートを利用可能に保ち、再構築されたクエリに依存するシナリオにはレディネスを考慮した確認を追加します。カスタムアプリケーションポートでは、テスト対象と現在固定されている起動プローブの両方に注意が必要です。

## プロジェクトの依存関係を管理する

`neo.json` はプロジェクトの依存関係を選ぶソースです。既存の `name`、`version`、`neo-version` フィールドを保ち、アプリケーションが追加パッケージを必要とするときは `dependencies` オブジェクトを編集します。`neo-version` はフレームワークのリビジョンを選び、`neo --version` で表示するインストール済み CLI のバージョンとは別です。

次の表はサポートされる構文です。パッケージ名とリポジトリは宣言形式の例であり、カートレッスンが必要とする依存関係ではありません。

| 依存関係のエントリ | 意味 |
| --- | --- |
| `"package-name": "^1.2.3"` | バージョンが範囲に一致する NeoPackages レジストリのパッケージを解決する |
| `"hackage:package-name": "^1.2.3"` | Hackage からパッケージを明示的に解決する |
| `"package-name": "github:owner/repository#revision"` | 指定した GitHub ソースとリビジョンを使う |
| `"package-name": "git:https://host/repository.git#revision"` | 別の Git ソースを使う |
| `"package-name": "file:../package-directory"` | アプリケーションと並べて管理するローカルパッケージを使う |

バージョン範囲には `^1.2.3`、`~1.2.3`、`>=1.2.3 <2.0.0` などの形式を使います。裸のパッケージ名は NeoPackages レジストリへ行き、Hackage へ暗黙にフォールバックしません。Git ソースにリビジョンがない場合はデフォルトで `main` になるため、再現性が重要ならレビュー済みのリビジョンを名前で指定します。

`neo.json` を編集したら、`mug-shop` から次を実行します。

```sh
neo build
neo test
```

生成された変更をレビューし、それを使うアプリケーションコードとテストと一緒に依存関係の選択をコミットします。再生成される `.cabal`、`cabal.project`、`flake.nix` ファイルを別に編集しないでください。このページで説明するバージョンには `neo add` コマンドはありません。

## アプリケーションを探索する

プロジェクトディレクトリから IDE を起動します。

```sh
neo ide
```

別の IDE ポートには `neo ide --port 2324` を使います。そのプロセスを実行したまま、2 つ目のターミナルから同じプロジェクトを調べます。

```sh
neo inspect
neo inspect commands
neo inspect wiring
```

`neo ide` はデフォルトで `127.0.0.1:2323` にバインドします。`--host` はホスト名ではなく IP アドレスリテラルを受け取ります。たとえば `--host 0.0.0.0` では、ほかの IPv4 インターフェースから IDE にアクセスできます。意図的に選びます。Ctrl-C でサーバーを停止します。

`neo inspect` は JSON を出力します。ビューには `domains`、`commands`、`events`、`queries`、`integrations`、`wiring` があります。ビューを指定しなければ、調べたプロジェクト全体を出力します。

`neo inspect sync` は**変更操作**です。ソースから `event-model.json` を更新します。既存フィールドの編集ではレイアウトを保てることがありますが、新しいノードではレイアウト作業が発生します。保存モデルを更新する意図があるときに使い、読み取り専用の報告には使いません。

このモデルの読み方は、[視覚的な IDE の道のり](/ja/getting-started/visual-ide/)を参照してください。

## 保存モデルを検証する

```sh
neo validate
neo validate ./event-model.json --json
```

検証は読み取り専用です。任意のパスは、現在のディレクトリにある `event-model.json` をデフォルトにします。スキーマと参照の整合性を確認しますが、ビジネスルールが正しいかは確認しません。

| 終了コード | 意味 |
| --- | --- |
| `0` | 有効なモデル |
| `1` | I/O またはツールの失敗 |
| `2` | モデルが検証に失敗 |
| `3` | JSON の形式が不正 |
| `4` | ファイルが存在しない |

`--json` は、人間向けログのプレフィックスなしで構造化された検証結果を出力します。終了コードの意味は変わりません。

## ドメインファイルを保護する

```sh
neo lock --all
neo lock Cart
neo lock install
neo lock check
```

`neo lock [search]` は、ドメインファイルをあいまい検索します。`--all` または検索なしでは、見つかったすべてのドメインファイルを選びます。マニフェストは `.locked-files` にあります。`install` は Git の pre-commit フックを書き込み、そのパスにある既存フックを上書きします。`check` は作業ツリーの変更を含め、ロックされたファイルの変更を検出します。[進化](/ja/operate/evolution/)で、この機能の背後にある過去の互換性問題を説明します。

ロックは選択したパスと `.locked-files` をステージし、Git コミットを作成します。先に `git status` を確認します。無関係な内容がすでにステージされていると、そのコミットに含まれる可能性があります。ロックフックをインストールする前に、既存の pre-commit フックを保ちます。

## 別のエージェントスキルをインストールする

```sh
neo skills setup --tool codex --dry-run
neo skills setup --tool codex
```

このコマンドは共有スキルライブラリを取得し、選択したツールにインストールします。人間向けのドキュメントは、これらの指示とは別です。

セットアップオプションは、繰り返し指定できる `--tool`（`claude`、`codex`、`kiro`、`cursor`）、`--all-tools`、繰り返し指定できる `--skill`、`--force`、`--dry-run`、`--refresh`、`--no-primer` です。`--dry-run` はプロジェクトへインストールせず計画を表示しますが、ライブラリの取得でローカルキャッシュが作られることがあります。`--force` は配置先の上書きを許可し、`--refresh` はライブラリを再クローンし、`--no-primer` は常時有効なプライマーとその instructions-file 配線を省略します。裸の `neo skills` はセットアップを実行します。

正しい情報源は[CLI 定義](https://github.com/neohaskell/NeoHaskell/blob/main/neo/src/cli.rs)です。失敗した場合は[トラブルシューティング](/ja/reference/troubleshooting/)を使います。
