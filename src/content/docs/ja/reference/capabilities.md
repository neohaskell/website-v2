NeoHaskell を使う前に、すべてのモジュールを学ぶ必要はありません。プログラムが実行する必要のある作業から始め、関係する概念を見つけ、現在の作業に必要になったら深く進みます。このマップは、フレームワークの構築ブロックと、チームが実装する必要のあるアプリケーション機能を評価する人が区別する助けにもなります。

`neo new` で作成したアプリケーションで続けます。ガイド付きプロジェクトでは、Cart と Stock のコードは `src/Shop/` の下にあります。下のリンクで、そこで各機能を使う方法を学べます。公開実装リンクは補助的な証拠を提供します。

## アプリケーションの振る舞いをモデル化して公開する

| 必要なこと | 機能 | 続ける場所 |
| --- | --- | --- |
| 要求された変更が許可されるか決める | コマンドと `Decider` | [アプリケーションを構築する](/ja/build/) |
| 受け入れられた事実を保つ | イベントとイベントストア | [永続化](/ja/operate/persistence/) |
| エンティティの現在状態を再構築する | エンティティとスナップショットキャッシュのインターフェース | [アプリケーションを構築する](/ja/build/) |
| 異なる読み手のためにビューを準備する | クエリ、クエリオブジェクトストア、ページネーション | [アプリケーションを構築する](/ja/build/) |
| コマンドとクエリを提供する | HTTP トランスポート、JSON、スキーマ/OpenAPI | [アプリケーションを構築する](/ja/build/) |
| アプリケーションを配線する | `Application` とサービス定義 | [はじめに](/ja/getting-started/) |
| アクションと読み取りを制限する | 認証、コマンドポリシー、クエリアクセス制御 | [セキュリティ](/ja/operate/security/) |

コマンド、イベント、クエリには、フレームワークの配線を生成する導出マーカーがあります。エンティティは、初期状態と更新動作を明示的に提供します。生成の仕組みを調べる前に、概念上の役割を学びます。

## アプリケーションを他のシステムにつなぐ

| 必要なこと | 機能 | 境界 |
| --- | --- | --- |
| 受け入れられた事実に反応する | アウトバウンドインテグレーションランタイム | ビジネス上の後続作業と失敗結果を定義する |
| 外部トリガーや時間指定の作業を受け取る | インバウンドインテグレーション | 入力を明示的なコマンドへ変換する |
| プロバイダーを呼び出す | HTTP クライアントとインテグレーションのリクエスト・応答型 | プロバイダー固有の契約には実装とテストが必要 |
| ユーザーのプロバイダーアカウントを接続する | OAuth2 同意、コールバック、シークレットストレージ | [プロバイダーアカウント](/ja/connect/provider-accounts/) |
| メールを送信する | Brevo と Azure Communication Services のインテグレーション | プロバイダー設定と配信確認が必要 |
| 言語モデル機能を追加する | OpenRouter、AzureAI、エージェント・ツールインテグレーション | 許可するアクションと結果の確認方法を定義する |
| 書類を処理する | ファイルアップロード、PDF、OCR、関連プロバイダーインテグレーション | バイト列を永続化し、アクセスを保護し、抽出失敗を扱う |
| 音声を処理する | 音声・文字起こしインテグレーション | 外部出力を失敗し得る入力として扱う |

これらのテーマは[インテグレーション](/ja/connect/)で追います。EC の練習用プロジェクトで組み合わせ方を示しますが、機能はドメインをまたいで使えます。汎用 HTTP クライアントにもプロバイダー契約が必要です。たとえば、すぐ使える決済・配送アダプターではありません。特定の実装が提供しない限り、ドメイン固有のルールとワークフローはアプリケーションの作業として残ります。

## 必要なときに言語の語彙を使う

コアライブラリには、`Text`、`Array`、`Map`、`Maybe`、`Result`、`Task`、識別子、日付、ロギング、関連するプリミティブがあります。トレイトは型をまたぐ再利用可能な操作を記述します。JSON・スキーマモジュールは、型付きデータを外部表現につなぎます。

システムモジュールはファイル、パス、ディレクトリ、環境アクセス、時刻、サブプロセスを提供します。並行性モジュールはタスク、チャネル、ロック、共有変数を提供します。これらは特定の必要に対する仕組みです。並行性を導入しただけで、サービスをまたぐビジネス操作が自動的にアトミックになるわけではありません。

言語に近いモジュールには、十進演算、解析、NeoQL ツールがあります。存在するからといって、完全な金額・税モデルや制限のないビジネスレポート言語を約束するものではありません。アプリケーションの実際の要件に対して、サポートされた操作、表現、境界テストを選びます。

見慣れない語彙が出てきたら、[言語の基本](/ja/build/language-essentials/)と[用語集](/ja/reference/glossary/)を参照します。

## 構築、調査、検証、運用する

| 必要なこと | 機能 | ドキュメント |
| --- | --- | --- |
| プロジェクトを作成して作業する | Neo CLI | [CLI リファレンス](/ja/reference/cli/) |
| モデルを視覚的に理解する | 組み込み Neo IDE | [視覚的な IDE](/ja/getting-started/visual-ide/) |

| フレームワークを改善する | 公開リファレンスアプリ、リポジトリツール、アーキテクチャ決定 | [貢献](/ja/operate/contributing/) |

ソースレベルの詳細は、リポジトリの[機能マップ](https://github.com/neohaskell/NeoHaskell/blob/main/codemap/capabilities.yaml)で、実装の所有者とテストを特定します。機能の一覧は調査場所を示しますが、頼れる振る舞いを確立するのは、具体的な例とテストです。

焦点を絞ったレシピは、[実践ガイド](/ja/guides/)を参照してください。
